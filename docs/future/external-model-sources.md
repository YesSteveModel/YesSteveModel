# 外部模型源

## 现状

通用外部模型源尚未实现：当前没有 provider 注册机制、配置项、目录拉取、资产绑定、凭据管理或独立传输层。

外部模型源与[独立 Backend](independent-backend.md)相互正交：Backend 是未来可选的远端玩家状态权威（并可附带模型服务），而外部模型源只负责提供模型目录与资产，可在 Local Only 或游戏服会话下独立工作，且不授予游戏服内权限。

## 目标与核心约束

- **身份与不可变目录**：每个 provider 使用稳定的 source ID、来源类型、优先级与独立游标（不以 URL、镜像地址或显示名作身份），产出携带 namespace、路径、descriptor 与逐条目访问策略的不可变 catalog contribution。
- **上下文原子绑定与隔离**：按强类型请求主体/选择器拉取资产，支持取消、关闭与限额；单次 provider context 原子绑定目录、游标、凭据与解析器，避免过期上下文或迟到结果跨刷新周期提交，并将错误、取消与关闭隔离在对应 context 内。
- **复用现有缓存与授权边界**：校验通过的资产接入既有远端缓存与发布链路，内容可下载与游戏服状态授权分开判定；缓存只按校验后的内容身份复用，来源私有的元数据、授权结论与游标不跨来源共享。
- **Java/Native 职责切分**：模型源接口与状态留在 Java 领域层，Native 侧仅提供归档读取、编解码、hash 或图像处理等无状态能力。
- **不可信输入与网络安全**：外部 descriptor 与资产沿用当前容器、Schema 及传输层的大小上限、结构完整性、解码长度与内容 hash 校验；各 provider 隔离凭据、配额、并发与磁盘预算；若支持 URL 下载，需约束协议 scheme、重定向策略、DNS rebinding、内网地址访问与超时。

## 演进思路

1. 在 Java 领域层定义 provider 生命周期、context 绑定与不可变 catalog contribution 接口；
2. 接入受限传输、凭据/配额隔离与完整内容校验，并复用现有远端缓存与发布路径；
3. 补齐取消、关闭清理与端到端验证后，再将该类外部源纳入支持状态。
