# 独立 Backend

## 现状

独立 Backend 尚未实现。当前仅具备权威模式选择与部分传输抽象；入站处理、握手、玩家状态同步及大部分控制逻辑仍绑定在 Forge 编排上。当前网络边界见[网络架构](../architecture/network/overview.md#职责与边界)，协议规范见[当前网络协议](../standards/protocol-v1/README.md)，进展见[当前支持状态](../status/support-and-verification.md)。

## 目标与核心约束

- **单一状态权威**：Backend 可作为当前游戏连接的唯一远端玩家状态权威（不与游戏服务端并存）。权威在连接建立阶段按既有规则选定（`AUTO` 依次尝试 Game Server → Backend → Local Only；`BACKEND` 仅尝试 Backend；`LOCAL_ONLY` 仅本地），同一连接内不热切换。
- **与外部模型源正交**：状态权威与[外部模型源](external-model-sources.md)独立；Backend 可只同步玩家状态，也可另行提供模型目录与资产。
- **与宿主解耦的传输绑定**：复用当前协议中适用的玩家状态与控制语义并定义独立传输绑定，不依赖 Forge、Minecraft 连接对象、JNI 或客户端 native 库，也不恢复已移除的历史资产分片协议。
- **会话与安全基线**：
  - 认证连接携带独立身份与代际标记（generation），凭据绑定到对应对端；写入主体身份由已认证对端决定（player ID 仅作路由）。
  - 双向传输覆盖发送、入站分发、断连通知、背压与发送完成信号；握手协商版本、特性集、资源上限与状态策略后原子激活，并隔离旧连接结果与彻底释放会话资源。
  - 若兼任模型分发，需补齐目录修订与重同步、权限/凭据校验、资产传输背压与取消，以及目录发布与会话的原子绑定。

## 演进思路

1. 抽离 Forge 回调，补齐与具体传输层解耦的入站、断连、握手与会话编排；
2. 落地带身份认证的状态权威与旧连接代际隔离；
3. 单独接入模型目录与资产分发（与外部模型源分轮交付）；
4. 完成协议一致性、畸形输入、取消、重连与多人联机验证后纳入支持范围。
