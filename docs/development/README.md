# 开发指南

按当前阶段选择入口。设计与实现指南各自承担总则和总览，专题只展开独立查阅的细节；产品、标准和子系统正文拥有实际契约。

## 理解代码与设计

以现有文档为主、源码检索为辅。从[文档入口](../README.md)定位产品契约、架构边界与复杂度子图，先形成判断和具体待核验问题，不无条件遍历源码或全仓索引。

源码检索用于核验影响结论的缺口、文档与行为冲突、职责替代关系及实际修改与验收。沿已发现的依赖定向查询，取得足够证据即停止。文档不能替代当前源码与运行验证，当前实现不能反向改写产品契约。

## 开发步骤

已有结论的依据和前提未变时直接继承，只处理本次变化影响的部分，不要求逐步创建文档。

1. **明确需求与决定**：确认问题、受影响用户和预期结果，从[产品决策](../product-decisions/README.md)定位依据。产品冲突交由人裁决。
2. **明确契约**：从[架构入口](../architecture/README.md)定位 seam，按[设计指南](design.md#契约与责任)明确责任、保证、失败和资源义务。涉及格式或协议时查阅[标准](../standards/README.md)。
3. **选择设计**：按[设计指南](design.md)比较机制与长期成本。涉及协调机制时，查阅[复杂度地图](../complexity-map/README.md)。
4. **实现与验证**：按[实现指南](implementation.md)建立和维持保证，维护声明、实现及受影响消费者，运行最小相关验证。
5. **审查**：按[分层审查](review.md)检查需求、决定、契约、设计和代码，说明验证结论及未证明范围。

产品行为契约规定承诺，seam 契约分配跨边界责任，代码契约细化调用和访问义务。各文档的阅读和维护遵循其入口规则。

### AI Coding 协作建议

推荐按开发步骤划分会话和阶段，使用任务文档传递各阶段的结论。可以按个人喜好封装并细化为本地 skill：

1. 在同一个会话内分两个阶段完成决策和契约。
2. 创建若干新会话，分两个阶段完成设计和实现。设计阶段可按需划分子任务，制定公共约束。若子任务数量大于 1，建议为每个子任务创建独立的会话。
3. 创建另一个新会话完成审查和验收。

每个会话不得自行修改任务文档中不属于当前阶段的信息。发现其他阶段的结论需要变更时，应交由用户或上层 agent 裁决并返回对应的上一阶段会话处理。

### 动画与渲染热路径

涉及动画更新或图形渲染热路径的开发任务，性能与正确性同等重要，且可维护性不得劣化。必要时可牺牲局部非承重正确性以保障性能，但应明确取舍范围、性能依据和行为影响。产品承诺与承重契约不得据此自行放宽。

此类任务通常需要人工参与设计、仲裁取舍、干预实现和最终验收，不应假定 AI 能独立完成上述权衡。AI 应提供可审查的方案与验证证据；涉及正确性取舍时，应由人确认取舍边界，并验收性能、正确性和可维护性。
