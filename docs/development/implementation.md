# 实现指南

本页约定代码落地的项目专属规则。上游契约与设计取舍见[设计指南](design.md)，Javadoc 声明语法见[代码契约](code-contracts.md)，基建入口见[基建指南](infrastructure.md)。

## 使用保证与保护责任

- **信任上游既定保证**：调用方直接依赖上游在当前窗口内建立并持续有效的内部不变量，不机械把接口前置条件逐条重查一遍。
- **增删保护的标准**：新增防御性检查（判空、二次状态确认、外层锁、拷贝、fallback、重试）须指明防范的独立失败源；删除既有保护须明确原职责已由哪个建立点接管，同时守住资源保活、地址有效性与容量上限底线，不混淆不同时点/身份的校验（例如内容校验通过 ≠ 后续无 I/O 错误，后台完成 ≠ 换代后仍有效）。
- 发现契约缺口或必须收紧前置条件/扩大失败面时，回退[设计指南](design.md#交付与变更)更新边界，不在实现里私自加限制。

## 数据与失败

- `null`、空集合、零值须有唯一语义，不能同时表达“正常不存在”和“内部失败”。
- 只在承担恢复、错误翻译、故障隔离或资源清理职责的边界捕获异常；日志记录与故障隔离分开决策，遵守[产品失败边界](../product-decisions/decisions/failure-isolation.md)。

## 代码契约

Seam 的类型、方法签名与 Javadoc 应足以指导调用方写出正确调用：类型注释写实例共享不变量、生命周期与架构关联；方法只写相对公共规则的增量要求，不复述类型签名已表达的条件。详细段落格式与示例见[代码契约](code-contracts.md#声明位置与格式)。

### 源码注释的文档引用

源码注释引用文档统一写成 `[说明](docs/路径.md#章节)`（相对项目根，`/` 分隔）；Java 符号用 `{@link ...}`。由 `docs/tools/check_docs.py` 自动校验锚点唯一性：

```java
/**
 * <p>Seam: implements [lease ownership](docs/architecture/model-management/client-resources/overview.md#引用撤销与物理关闭).
 */
```

## Java 类型命名

- 包名表达模块归属，类名表达职责。内部类型**不加 `Ysm` 前缀**（仅消歧时加领域词，如 `MolangContext`、`ModelSoundId`），接口与实现**不用 `I`、`Impl`、`Production` 机械后缀**。
- 常用后缀：`State`（可变状态）、`Binding`（绑定关系）、`View`（访问视图）、`Scope`（生命周期作用域）、`Catalog`（目录）、`<Domain>Builtins`（内建成员）、`<Domain>Component`（有状态组件）、`Capabilities`（能力/资格）、`Handler`（事件处理器）、`Event`（事件载荷）。
- `YsmExtension`、`YsmEventHandler`、`YsmEntityComponent` 等面向第三方模组接入的公开入口保留 `Ysm` 前缀。重命名类型不得改变 Molang 名称、资源 ID 或网络协议标识，并须同步更新反射与服务注册引用。

## 基建复用

现有门面满足职责时直接复用，缺少量能力优先扩展原门面；仅在职责定位、生命周期或性能约束明显不同时引入新机制。详见[基建指南](infrastructure.md)。

## 变更与验证

- 修改契约或实现时，沿 seam 传播复核消费方、异步回调、扩展入口与拒收路径，同步更新对应文档与已知差异。
- 优先复用既有测试，仅在存在证据缺口时补充；**测试替身只能通过显式架构 Seam 注入**，禁止为了单测给生产类添加多参数测试专构、生产零实现故障注入 `Hook` 或白盒计数方法。
- 分层投入尺度与测试红线见[验证边界](../verification/policy.md)。
