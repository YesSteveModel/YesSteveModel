# 实现指南

本页定义实现总则，负责建立和维持保证、消费依赖及完成变更验证。输入是[设计指南](design.md)确定的契约与责任；声明格式见[代码契约](code-contracts.md)，现有能力见[基建指南](infrastructure.md)，验收见[分层审查](review.md)。

## 实施原则

明确问题、假设和可验证结果，核对设计与实时源码。修复缺陷时优先复现并修复根因；已有依据及前提未变时继承结论。契约缺口、冲突或可观察行为变化返回对应设计阶段，产品含义冲突交由人裁决。

只修改本次变化及必要的受影响依赖，保留用户已有改动。替换机制时承接有效责任，删除失效路径与残留；多种方案影响行为或长期成本时，按[设计总则](design.md#从结果选择机制)说明取舍。

目标设计已确定，且方案满足契约、必要变更闭环与验证要求后，不为寻找更短代码继续枚举替代方案。只有具体缺陷、未解决疑点或成本证据才重开比较。

简短、单次使用且依赖局部上下文的逻辑默认就地表达。抽取函数应带来复用、复杂逻辑隔离、资源或副作用作用域收敛，或减少理解所需细节；仅转发参数或预留未来复用不足以支持抽取。

需要分工时，按可独立交付和验证的结果拆分任务。开始依赖任务前，明确共享接口、资源责任和依赖，并指定整体集成与验证责任方。

## 使用保证与保护责任

依赖 seam 时，读取其显式共同规则、实际依赖和代码声明。首次依赖、条件变化或出现反证时，核对保证的建立入口、维持者和有效窗口；建立点覆盖入口，维持者控制可能破坏保证的行为。

调用方信任已建立且持续有效的内部不变量。提供方维持结果保证并覆盖失败、取消、拒收及未交付资源；调用方承担输入、组合、恢复和归还义务。同仓库、同进程、注释或历史验收本身不建立运行时保证。

增加或删除保护时，指出尚未覆盖的独立失败来源、责任方和有效窗口。前置条件不逐项转成运行时检查。

| 保护 | 核对内容 |
|---|---|
| 判空、范围、完整性或输入校验 | 建立与变更入口是否受控，保证是否覆盖本次需求和使用窗口 |
| 捕获异常、fallback | 当前层是否拥有恢复、翻译或隔离责任 |
| 外部锁、屏障 | 并发粒度、可见性和失效排序是否已覆盖 |
| 关闭、就绪或身份查询 | 操作是否原子裁决，资格是否持续有效，查询是否仅为快照 |
| 防御性拷贝 | 数据是否不可变，借用窗口是否排除修改和释放 |
| 重试与恢复状态 | 重试裁决、重复副作用和资源责任是否已覆盖 |

删除保护时，说明原责任由哪个建立点或机制承接，或因合法行为收窄而消失。资源保留、地址和容量安全仍须落实；身份、时间或可变性不同的检查分别判断。已验证内容仍可能发生 I/O 失败，完成的计算仍可能因接收方换代失去资格。

缺少契约信息时，定位事实 owner 并补齐对应层次的声明；实现缺口链接 status。原保护承担的责任应先闭合，再移除重复机制。若候选保证无法建立，修复建立或维持责任，或撤回简化。

## 数据与失败

`null`、空集合和零值各有明确含义，不同时表示正常缺失和内部失败。只读容器不保证元素不可变；值对象只有在构造及变更入口受控时，才能免除下游重复校验。

只在承担恢复、翻译、隔离或清理义务的位置捕获异常。违约保留原因和责任身份；诊断与后果隔离分别裁决，遵守[产品失败边界](../product-decisions/decisions/failure-isolation.md)。清理按资源契约执行，重试按接口的身份及幂等性条件裁决。

## 代码契约

Seam 的类型、签名和声明处应足以指导正确调用。共同生命周期、不变量及架构关联放在类型；方法只补充调用差异；字段只声明消费者依赖的约束。实现内部记录建立和维持保证的机制及非显然理由。

使用普通 Javadoc；参数、返回值和异常使用标准标签，其他内容按[声明格式](code-contracts.md#声明位置与格式)组织。类型已表达的条件不复述。架构与代码的责任连接见[契约映射](code-contracts.md#与架构契约的连接)。

### 源码注释的文档引用

源码注释使用 `[说明](docs/路径.md#章节)`，从所属项目根目录解析，路径使用 `/`。Java 符号使用 `{@link ...}`；Markdown 文档内部链接相对当前文档解析。文档引用由 `docs/tools/check_docs.py` 检查，不依赖 Javadoc 的 HTML 链接解析。

```java
/**
 * <p>Seam: implements [lease ownership](docs/architecture/model-management/client-resources/overview.md#引用撤销与物理关闭).
 */
```

## Java 类型命名

包名表达归属，类型名表达职责。内部类型不加 `Ysm` 前缀，仅为消除歧义使用领域限定，例如 `MolangContext`、`ModelSoundId`。接口与实现均按职责命名，不用 `I`、`Impl` 或 `Production` 区分。

`State` 表示可变状态，`Binding` 表示绑定关系，`View` 表示访问视图，`Scope` 表示生命周期作用域，`Catalog` 表示目录。内建成员提供类使用 `<Domain>Builtins`，有状态组件使用 `<Domain>Component`；`Capabilities` 表示能力集合或资格描述。事件处理器使用 `Handler`，载荷使用 `Event`。

`YsmExtension`、`YsmEventHandler`、`YsmEntityComponent` 保留前缀，明确第三方接入目标；产品入口和具体格式名也可保留。Java 类型重命名不改变 Molang 名称、资源 ID 或协议标识；同步更新生成源码、反射名称及服务注册中的类型引用。

## 基建复用

现有门面能承担职责时直接复用，契约不足时优先扩展原门面。职责、生命周期或性能约束不同且无法合理扩展时，才新增机制，并说明维护成本。能力选择及领域接入见[基建指南](infrastructure.md)。

## 变更与验证

同步维护权威正文、建立与维持机制，沿具体 seam 的消费者、组合契约及上下级传播，在责任不受影响处停止。复核输入、异步投递、回调、扩展、旁路构造和拒收路径；共同规则变化覆盖其显式继承者。

需求或共享设计变化后，复核受影响的任务、实现和证据，包括已完成部分；仍成立的结论继续复用。

只细化局部调用义务且架构保证不变时，维护声明、实现和调用者。前置条件收紧，或失败、资源后果改变时，返回[设计指南](design.md#交付与变更)重评架构。

拆合或迁移契约时保留义务、例外和理由，修复引用含义并删除重复正文。交接、发布资格、资源终态和多域依赖使用可精确引用的语义章节；引用方说明依赖与前提，保持未变语义的标题稳定。

按影响选择能击穿保证的入口或竞态，运行最小相关验证。优先复用覆盖变更契约的现有验证，仅为具体证据缺口新增测试。相关检查通过后，除非出现新改动、失败或未解决疑点，不扩展或重复验证；不免除已规定的集成验证和独立审查。已有证据且前提未变时可继承，投入及结论遵循[验证边界](../verification/policy.md)。同步维护验证入口和 status 差异。

交付说明实际改动、必要理由、验证命令与结果、未完成项和限制，使审查者无需重演实施过程。
