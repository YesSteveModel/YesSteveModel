| AP-01 独立调用者冻结实际解析闭包 | Builtin 与显式 export 通过 capture 深拷贝实际读取到的字节，并复用同一套 parser。Catalog 对 raw、ZIP、7z、v1 和 v2 直接做完整解析，来源稳定性由调用方负责；只要媒体数据需要跨下一次 archive 提取保留，就必须拷贝成自有字节。 | `A-CAPTURE`；**Derived**。Catalog 已不再通过冻结 VFS 后重跑 parser 来维持输入一致，但独立的 capture 仍继续承担 builtin 与 export 调用方的冻结职责。 | **Fact**：`ModelParser.capture`、`ModelParser.compile`、`CapturedSourceData.freeze`、`RawModelImporter.convert`，以及[来源转换](../../architecture/asset-pipeline/overview.md#冻结输入与单向转换)。借用 buffer 的回归测试通过对比稳定输入与复用 buffer 的完整输出验证行为，不能仅凭提示信息匹配就推导源 payload 完整。 |
| AP-02 按读取对象验证 | 只有在实际读取 metadata 或 preamble 时，才校验结构与 CID。Manifest 与普通 chunk 一样，按当前可信 descriptor 校验边界、长度、编码与哈希，通过后再解释身份与引用。索引候选阶段不触发容器 I/O，也不预检尚未消费的 chunk。 | `D-META`、`D-VERIFY`、`D-IDENTITY`、`D-FREEZE`；**Essential**。按需访问、精确表示以及开发制品门禁仍然成立。 | **Fact**：`VersionCompatibility`、`AssetContainerReader`、`ModelFileView.readMetadata`、`ChunkDecoding`，以及[分层验证](../../architecture/asset-pipeline/implementation/container-and-validation.md)。Direct、converted 与 remote 共用同一套对象边界，保留完整的生产与离线验证；缓存中的普通读取失败按 miss 处理，控制类失败则继续向上传播。 |
| AP-03 Raw PNG 的用途驱动重编码与失败回退 | Raw 转换会直接复用合法的 JPEG、WebP、AVIF 等既有压缩表示，只让 PNG 进入用途驱动的重编码策略。只要编码成功就采用新结果（即便产物变大），只有遇到可处理的 codec I/O 失败时才回退保留原图。如果删掉格式门禁，会重复重编码既有压缩图；如果删掉失败回退，原本可用的输入会变成转换失败。 | `D-IMAGE` 与 `A-IMAGE`；**Derived**。按用途保真的产品义务不可删除，但输入门禁、codec 与尺寸策略以及失败回退本身属于可替换方案；legacy 解码期的图片归约另归 NR-17。 | **Fact**：`RawImageCompressor.compress`、`ImageEncoder`；`RawImageCompressorTest` 验证了压缩复用、结果采纳与失败回退；详见[处理位置](../../architecture/asset-pipeline/implementation/conversion-and-export.md#图像处理的位置)。策略效果与成本的证据缺口见 [Q-04](open-questions.md#q-04)。 |
| AP-04 连续页面需求与迟到结果处置 | Coordinator 的 `PageScope` 保存页面语义成员、稳定卡片端点与连续停留起点，统一计算模型和图片的分级准入。`PageImages` 负责图片的惰性获取、提交、slot 结束状态与独立图片使用计数；`ResidentImages` 集中维护内容关联和消费者计数；manager 保留唯一的物理释放权。相同内容的页面重建或缩放会保留原 scope 与实体，只有页面内容真正变化时才封口旧 scope。每帧新准备名额通过循环游标公平分配，即便提交被拒绝游标也会推进，而已有绑定的动画更新不占用新准备名额。同一张卡片获准的 Ready 绑定与冷图 CPU 准备归入同一次任务，多卡共享的图片只交给一个解码任务。页面绑定当前世界流程，资源 action 绑定原连接；活跃帧完成交接后才结束页面使用，迟到结果不能复活已封口的旧页面。目录层级用完整地址隔离来源并在展示时隐藏来源前缀；Ctrl 路径动作只消费已发布位置或已验证的本地证明，不进入 demand。如果删除该机制，短命页面会过早触发准备，内部重建会反复等待，突发准备失去容量限制，图片也可能悬挂泄漏。 | `D-GUI`、`A-PAGE`、`A-CONTINUOUS-DEMAND`；**Derived**。页面、图片宿主和共享资源的职责依然分离，只是不再各自保存一套需求规则。这套机制的成本在于维护活跃 scope、循环游标、帧内任务与共享图归属、图片 slot 推进、资源侧内容证明和引用计数（驻留命中优先于重新获取）。公平预算与任务分组可以替换为能保持“同次任务、持续推进和退出交接”的等价调度；如果删除共享图片 owner，系统会退回逐页读取、解码和注册，因此只有当宿主侧具备等价的内容关联与独立消费者管理能力时才可删除。另外，图片提交时会固定生成用途，批量结果与宿主在接纳点转移独立像素能力，取消操作不依赖旧页面继续推进；传输结束后逐条交付图片，不让整批完成阻塞单张图片的交接。 | **Fact**：`ClientDemandCoordinator.PageScope`、`PageImages`、`CatalogPageFrame`、`GuiFrameTasks`、`ClientDemandCoordinatorTest`、`GuiFrameTasksTest`，以及[页面 owner](../../architecture/client-presentation/implementation/page-runtime.md#页面与资源-owner)。Repository 仍保留精确对应的 action、ABSENT 处理和 cache 提交；实机反复翻页与纹理回收尚未验证。 |
| AP-05 展示资格与独立 GUI 准备 | 展示资格由配置与连续交互共同授予：自动 GUI 准备最多走离线路径，交互触发的准备还要同时满足页面准入约束。光标移出后撤销展示、安装与私有动画用途，已接纳的准备仍归原 owner 管理。GUI 与 FULL 各自独立获取使用权：帧接收方先保留 lease，页面在原 join 完成后再根据 binding 中真实的 `installedRequest` 退役来源 anchor。遇到 Busy 时保留候选，不再使用旧的 claimed / complete 回报协议；纹理入口只接收完整的 Ready 资源。 | `A-PREVIEW`、`D-JOIN`、`A-CONTINUOUS-DEMAND`；**Derived**。它需要保留稳定卡片端点、临时实体、用途 anchor 和每帧独立借用，但已删去另一份冗余的安装完成状态。自动准备只创建默认 body，GUI 不探测也不借用 FULL，中央预览则单独获取 FULL。 | **Fact**：`ClientDemandCoordinator`、`EntityModelDemand`、`CatalogPageFrame`、`CatalogModelCardState`，以及[页面主流程](../../architecture/client-presentation/implementation/page-runtime.md#页面主流程)。来源封口不会关闭已交接给当前帧的使用；生产接缝测试覆盖了状态交接，但不能外推为全部 GPU 外观与长期显存回收均已验证。 |
| AP-06 转换 staging 与重开验证 | Raw 与 legacy 转换都先写出独立的 staging 产物，重新打开并验证身份、逻辑 payload 与存储描述后，才交由 converted object 或目录候选接收；一旦失败立即清理本次半成品。如果删掉这道门禁，就会把“转换过程没报错”误当成“当前容器可读”，甚至向外暴露损坏的半成品。 | `A-ONE-ARTIFACT`、`D-FREEZE`、`D-SOURCE`；**Derived**。跨输入格式统一出口带来了产物交接与复验成本，而用户来源只读与内容完整仍是独立义务。 | 架构事实见[转换出口](../../architecture/asset-pipeline/implementation/conversion-and-export.md#发布与失败)和[单向投影](../../architecture/asset-pipeline/implementation/conversion-and-export.md#历史输入的单向投影)；验证入口为 `LegacyModelImporter.stage`、`RawModelImporter.convert`、`ConvertedObjectStore`。当前仍保留对 staging 容器的重开复读策略，文档规则不替代完整的 golden 与真实导入测试。 |
| AP-07 实际来源准入与 schema 分离 | Schema reader 接受合法的无图容器；Catalog 只在实际读取 Manifest 时，对 direct 成品要求内嵌 preview 声明，并在读取图片时再验证 payload，而 raw、builtin 与 legacy 的内部结果允许缺图。来源类别由 resolver 调用链固定，不能靠文件扩展名、`origin_ver` 或 cache 猜测。如果取消这种分层，要么会误拒合法的内部来源，要么会让缺图的 direct 成品绕过产品门禁。 | `A-DIRECT-ADMISSION`、`D-SOURCE`；**Derived**。按来源区别准入是产品选择，单独设立 policy gate 是当前实现方案。 | **Fact**：`DirectContainerAdmission.requireEmbeddedPreview`、`ModelSourceResolver.resolve`、`ModelSourceResolver.resolveMaterialized`，以及[preview 与 export](../../architecture/asset-pipeline/implementation/conversion-and-export.md#preview-取得与显式-export)。完整来源矩阵与跨平台媒体尚未完全验证。 |
| AP-08 弱关联 preview cache 与完整 export | 独立预览图只按 `ContainerId` 弱关联，普通服务端读取不做解码，并与 chunk 共用同一套字节 runtime。唯一 store 的持久写入成功或显式 reload 会撤销旧缓存及旧 flight 的发布资格，活动 lease 与物理容量仍由原 owner 维护；严格提交（strict commit）在原 session 和 member 资格内原子替换，异步通知不会反转已持久化的结果。客户端 tick 上的总操作准入跨 probe、target、宿主上传与写出全程持有容量与结束责任；integrated environment 额外固定导出批次、精确输入与提交资格，并在结束时撤回自身需求。如果删除独立 cache，图片会被反复拉取；如果回写原容器，会引发身份与目录循环；如果删掉总准入，候选资源、像素和来源就会无界驻留。 | `A-PREVIEW-CACHE`、`A-WORK`、`D-FREEZE`、`D-SOURCE`；**Derived**。来源保护、完整导出与可靠结果属于产品义务，而弱关联、共享字节保留、替换资格、串行批次和统一准入属于可替换设计。当前方案删去了平行读取链，但新增了一个旧 flight 存活集合以及提交和 reload 时的失效成本。图片版本在原替换门禁内同步更新，不依赖尽力通知，通过独立图读结果、session 成员观察和 Catalog reload 共同防止旧像素被发布；如果原 owner 直接提供等价版本能力，该机制可删。封闭内容会复用媒体资格，由原操作直接派发解码，独立像素引用和同步借用一直保留到实际使用结束——代价是退役处理、能力交接与取消清理，换取的是消除同一次存储与上传过程中的重复解码，且不再协调客户端字节额度。 | **Fact**：`ClientPreviewGenerator.tick`、`PreviewStore`、`ServerResourceRuntime`、`PreviewRepairBatch`、`ServerPreviewWork`、`ModelExporter.export`、`ModelExportService.Environment`；时序与容量归属见[preview 与 export](../../architecture/asset-pipeline/implementation/conversion-and-export.md#preview-取得与显式-export)、[共享字节保留](../../architecture/model-management/server-resources/overview.md)和[管理传输](../../architecture/network/implementation/asset-transfer.md#receiver-local-assembly-与-publication)。本机制共享 render owner 与 target 能力，局部测试与宿主证据范围见[模型管理问题](../../status/known-issues/model-management.md#导出与管理补图)。 |
| AP-09 音频规范化、完整计价与分层验证 | Raw 与 legacy 声音统一转换为当前音频表示；对高包率 Opus 在 R 与 T 两种候选间做选择时，直接复用实际 writer，结合固定其余内容计算完整容器长度。验证分为三层：M1 只检查 descriptor 与定位，prefix 只获取首块，M2 顺序送入全部块直至 EOF；export 则原样复制并重开复验。如果删掉统一表示，生产端与消费端会在 codec、帧结构或布局上产生分歧；用估算公式替代实际 writer 会改变候选选择；把 M2 并入目录浏览则会提前预读所有音频内容。 | `D-SOUND`、`D-MIGRATION`、`D-JOIN`、`D-CHUNKS`；**Derived**。声音可播放、单向迁移和按需读取属于产品义务，而候选选择、首块定位与分层验证属于当前实现方案。 | **Fact**：`RawModelAssembler`、`SoundMediaGeneration`、`SoundMedia`、`LegacyModelImporter`、`BuiltinModelMaterializer`、`ModelExporter`，以及[音频转换](../../architecture/asset-pipeline/implementation/conversion-and-export.md#音频内容转换)。局部测试已覆盖候选选择与完整验证，来源、平台与游戏内覆盖范围见[格式问题](../../status/known-issues/format-and-schema.md#codec导入与平台)。 |
