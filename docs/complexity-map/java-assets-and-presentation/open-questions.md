# 因果缺口与差异

本页只维护 AP 子系统中尚未确认的判断。产品选择仍以[产品决策树](../../product-decisions/README.md)为 Root Authority，下面列出的实现事实不会自动构成例外。

## Q-04

**用途驱动图片策略的效果与成本证据尚不充分。** [图片产品边界](../../product-decisions/decisions/image-policy.md)要求保持整体视觉效果，但当前的 codec、尺寸阈值，以及 raw 回退与 legacy 来源局部失败这两套不同处置，尚未被证明满足该目标。具体处理顺序与格式规则见[转换与导出](../../architecture/asset-pipeline/implementation/conversion-and-export.md#图像处理的位置)。

后续调整需要对比复用、缩放、峰值内存与重编码开销，不能仅凭体积缩小就认定整体视觉保真，也不能因为“编码成功”就推定产物成本已改善。最小验证矩阵应覆盖已有 JPEG、细长小 PNG、RGBA32、不同用途尺寸及 Android 策略，检查分辨率、色彩与透明边界、整体视觉、产物体积和峰值内存，并分别验证 raw 的失败回退与 legacy 的来源局部失败。对应机制为 AP-03 与 NR-17。

## 其他证据缺口

AP-04 与 AP-05 的集中规则、零缓存 lease 交接和协议反馈已有自动化测试，但分级准入的工作量与可见延迟、真实 FULL 冷延迟、30 秒初值、Busy 帧成本与画面表现仍需实机或对应采样。此外，AP-05 真实 3D 选模的体验收益、AP-08 离屏渲染的画面与冷热启动成本、实机页面反复翻页和纹理回收也尚未验证。这些缺口限制了收益和可靠性结论，但不代表现存机制可以自动降为 `Historical`。
