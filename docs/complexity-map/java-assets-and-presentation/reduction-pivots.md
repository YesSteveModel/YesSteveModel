# 归约支点

本页维护由 AP 子系统主导的归约支点，并索引其他子系统主导的相关跨域支点。

| 支点 | 最小改变 → 可减少部分 | 剩余义务、成本与最小验证 |
|---|---|---|
| V-10 重新选择帧预算或预览方式 | 放宽 frame budget，或改为仅展示静态卡片，可分别缩减 MN-13 或 AP-05 的局部状态。 | 放宽帧预算不能消除所有大动作，且必须重新验证宿主背压；改为静态卡片会改变选模体验，但 AP-04 的页面需求管理与 AP-08 的图片获取和 export 依然存在。整体为中等成本，需分别测量帧队列表现与真实选模体验价值，不能把两项改动捆绑在一起导致收益无法归因。 |

相关跨域支点：

- [表示替代规则](../java-models-and-network/reduction-pivots.md)会影响 AP-02 的分层验证，但由 MN 侧的表示选择主导。
- [显式拥有 archive bytes](../native-capabilities/reduction-pivots.md)可消除 AP-01 的跨子系统复制时点耦合，但不会去掉输入一致性义务。
- [维护与复杂度归约规则](../governance/maintenance.md)定义了替代承接和旧路径退出的判定条件。
