|---|---|---|---|
| MN-01 增量 candidate 与单点发布 | Catalog 独占扫描激活与结果接纳，前置登记和扫描共用同一个活跃身份。独立协调线程归并无损扫描结果并构造完整 index 与 snapshot，再由 owner tick 接纳最新槽位与结束状态。候选健康状态与根目录完整性分开判断：损坏分支保留健康兄弟，损坏新项保留旧项；最终发布门禁按 CACHE 根目录分组，失败组不确认删除也不回滚已成功项，健康组独立完成发布。普通同身份项按本轮首次完整接纳占位，不再维护 AUTH 路径优先级，全局位置与实例位置各自独立生成视图。复用旧图时按完整值比对，独占新结果与共享引用分开释放；前置等待在 owner 锁外执行，关闭时不等 tick。同一轮活跃扫描发布不可变的阶段与输入计数供 HUD 和页面单次读取，结束状态经 owner 接纳后才隐藏，关闭时等待生产者结束；进度视图增加逐项短期对象，不参与 current 状态、发布或完成判定。直接删除完整构造会暴露新旧混合目录；把归并放回主线程会带回随目录规模增长的主线程开销；改成整轮同步屏障又会阻塞有效内容的及时发布。 | `D-RELOAD`、`D-CATALOG`；**Essential** 仅指完整条目、一致目录与有效项及时可用。启动提前量、固定线程策略、构造线程、交接槽位及复用策略均可替换，且不证明前台延迟收益。 | **Fact**：`ReloadableModelCatalog.ActiveScan.run/tick`、`CatalogReconciler.resolveIncremental`、`ResolvedContent`；[reload](../../architecture/model-management/catalog/overview.md#seam-contract)。本轮祖先栈与目标观察不形成持久链接表，同一目标的别名可能重复验证；同根分组共用完整性门禁，其他 CACHE 根目录独立确认删除和维护资格。冲突与复用成本见[发布设计](../../architecture/model-management/catalog/overview.md#seam-contract)；主线程通知链仍有独立开销。 |
| MN-02 Publication、activation、Ready 分离 | 目录集合（Collection）先提交权威事实，条目在校验 metadata 后进入 Ready 目录，对应目标资源继续按需获取。完整公开地址贯穿 catalog、pack 与 selector，但不作为第二套模型身份。内容成员发生替换时取消旧的 Pending metadata 请求；仅资格变化时保留已接纳的动作并重新绑定到当前条目。接收方在发起新 acquire、命中缓存或触发新声音播放前均查询当前内容资格，但不会撤销已有旧 lease，也不会把无权使用记成内容失败。直接删除这层分离，会把单个损坏条目扩大成整体失败，把 metadata 误当成完整目标资源，或让缓存绕过授权授予新的使用。 | `D-JOIN`、`D-CHUNKS`、`D-ACCESS`、`A-NOTIFY`；**Derived**。分阶段可用和按当前授权校验是产品义务，当前的 snapshot 与 activation 负责方划分属于实现选择。 | **Fact**：`ClientSessionRuntime.applyCollectionResult/completeActivation`、`RemoteCatalogActivation`、`ClientCatalogSnapshot.permitsRuntimeContent`；[catalog sync](../../architecture/network/implementation/catalog-sync.md)。用单个条目的布尔标记配合统一的 full 与 delta 视图，替代实体级权限镜像；策略变更时需扫描接收方目录计算差异。权威事实先于通知提交，通知失败不回滚事实，且不靠 ACK 或历史重放保证即时同步。 |
| MN-03 业务身份与精确表示 | 目录发布保留完整 `ModelId`、位置和访问权限，实际表示与存储区域另行绑定。命名身份只允许 `ContainerId` 相同的本地替代，hash 身份保留已验证的同源例外。直接删除精确匹配条件会把同名但内容不同的模型混用；统一要求所有来源字节精确匹配，则会增加 hash 同源模型的重复下载。 | `D-IDENTITY`、`D-REUSE`；**Essential**，两种等价关系直接来自产品决策。 | **Fact**：`ModelId`、`RemoteCatalogActivation`；[身份](../../product-decisions/decisions/model-identity.md)。路径摘要仅用于适配物理文件名，不是第三种业务身份。 |
| MN-05 精确读取实例与完整文件发布 | 每个读取实例固定来源、存储区域、profile 与实例标识，并在 reopen 和迟到任务中持续保留。`direct` 分支只读原件；`converted` 分支在实际读取时校验 preamble 与 CID，Manifest 和普通 chunk 按消费进度校验。内容错误（CONTENT）只撤销实际 `converted` 对象的有效资格，保留来源事实，既不删文件也不广播下架；同一 CID 重建后获得新的实例标识。完整文件先生成并校验，再经短事务发布索引，失败允许残留孤儿文件或读取 miss。直接删除实例边界会让旧反馈误撤销新重建结果；删除完整提交会向读者暴露半份文件。 | `D-EXACT`、`D-SOURCE`、`D-REUSE`、`D-HOLD`；**Derived**。 | **Fact**：`ContentStorageBinding`、`RuntimeContentStore`、`ConvertedObjectStore`、`StorageIndex`；[精确读取](../../architecture/model-management/storage/overview.md#用户来源与精确读取)。已验证资源独立有效；ACCESS 错误、主动取消和 OOM 均不撤销索引。物理文件清理归 MN-24 负责。 |
| MN-06 Ready 可达性、独立 lease 与 unused LRU | Ready 缓存按精确的 role、content 和 profile 键保存缓存引用与活跃消费者计数。最后一个消费者退出后，条目进入受配置数量限制的 unused LRU 队列；再次获取时移出 unused 队列；超限时只撤销缓存引用。如果任一消费者退出就直接物理关闭资源，会破坏其他实体正在使用的 target；按对象地址、空闲时间或 lease 总数计数则会误复用或误淘汰。 | `D-HOLD`、`A-RESOURCE`；**Derived**。独立消费者安全与[保留数量策略](../../product-decisions/decisions/device-quality.md#bcdevice-derived-configuration-defaults)属于产品义务，`D-HOLD` 仅约束已有使用存续；可达性与 LRU 的数据结构可替换。 | **Fact**：`ModelRenderTargetCache.acquire/release/trimUnused`、`ResourceLease`；[所有权](../../architecture/model-management/client-resources/implementation/resource-ownership.md)。默认模型通过必需的 required lease 持有，不依赖 pin 或 preload；物理回收没有同步时间上界。Pending 取消另归 MN-17 负责。 |
| MN-07 Domain 有限工作与 owner-tick 提交 | Catalog 以及客户端、服务端 runtime 各自接纳有界工作链，计算 worker 线程不阻塞等待网络、宿主线程或其他 worker。服务端的 chunk 与独立图读取共用字节 runtime；旧图对应的 flight 失去加入资格后，仍占用容量直到物理结束。客户端在原有容量内为本地玩家划出专用 worker；Dispatch 集中决定同节点任务迁移、领取与排空，原 owner 保留取消权与结束判定权。直接删除工作隔离会让本地玩家排队等待后台长队列；把调度器变成业务 owner 会引入第二套完成权威。 | `A-WORK`、`D-LOOP`；**Derived**。主循环不阻塞与独立容量边界属于义务，队列和 worker 形态可替换；固定专用容量会减少一个后台计算并发槽位。 | **Fact**：`ClientResourceScheduler`、`ReloadableModelCatalog.ActiveScan`、`RuntimeContentStore`、`ServerResourceRuntime`、`ClientModelRenderTargetManager`；[有限工作理由](../../architecture/runtime/overview.md#有限工作调度与领域交接)与[客户端调度](../../architecture/runtime/overview.md#客户端资源调度)。精确会话关闭时不排空共享 worker；显式受控域关闭时先结束各业务 owner，再封口并排空调度器；JVM 退出时直接放弃后台工作。 |
| MN-08 Required default 内存闭合与固定驻留 | 启动时先校验 jar 内置原始来源的真实 `ModelId`，再直接生成常驻内存的容器并保留独立的 required 槽位。客户端完成全部可请求 target 与纹理的 FULL 和 GUI 准备，服务端完成本侧只读内容准备后，才发布 required 候选。直接删除这层启动期完备准备，会让首次 fallback 变成另一次可能失败的异步加载；改回临时文件会重新引入交接与清理负担。 | `D-DEFAULT`、`A-DEFAULT-MEM`、`D-FALLBACK`；**Essential**。 | **Fact**：`BuiltinModelCatalog.generateDefault`、`ManagedContainer.openResidentDefault`、`ClientModelRenderTargetManager.startRequired`；[默认基线](../../product-decisions/decisions/model-fallback.md)。同源的普通 builtin 模型单独进入常规目录、运行准备、失败记录与 lease 生命周期；烘焙 profile 与缓存仍按 NR-05 独立处理。 |
| MN-10 选择操作与实体安装 | Coordinator 准备完整 MAIN 字典、初值与持久化资格；本地提交时先让旧 producer 退役并建立新 scope，再尝试发送一次网络请求。binding 只保存目标选择与操作记录，以及当前实际使用的模型（usage）；`EntityModelDemand` 根据这两项事实派生候选请求和 Busy 重试。候选对象捕获原操作、主体、用途、binding 和精确内容，并在安装时复核；同值重选会重建私有执行状态，兼容纹理原位保留。旧的合法 usage 可暂时留用，但不能以新选择意图对外上报。 | `D-FALLBACK`、`D-HOST-FALLBACK`、`D-GUI`、`A-CONTINUOUS-DEMAND`；**Derived**。设计上取消了对 Accepted 或 self 回显的等待以及独立 assignment 层，保留独立 lease、用途锚点与安装资格校验。 | **Fact**：`ClientDemandCoordinator`、`EntityModelDemand`、`EntityModelBinding`；[选择反馈](../../architecture/model-management/demand/overview.md#选择反馈)与[安装](../../architecture/animation/entity-lifecycle.md#模型使用与完整安装)。资源、Flight 与宿主纹理发布归 MN-06 和 MN-17–19；失败记忆与重试资格归 MN-20。 |
| MN-11 Exact session、业务准入与迟到隔离 | 消息入队与应用前都会核验是否为同一个 `Connection`。握手阶段，`Hello` 先经过无状态的开发版本校验，只有在 `ACCEPT` 完成传输提交后才建立稳定 `BusinessSession`；选择请求、玩家状态与控制消息不等待目录进入 `ACTIVE`。协议失败或断连会撤销业务资格，目录失败则只关闭目录发布与资源负责方；目录发布和资产传输各自维护非零递增 ID，已结束的旧项不会重开。Session 不保存第二份可变选择，只读取 capability 视图，关闭会话时顺带退役其 producer。Session 还为当前成员持有有界的预览观察与 token，收到通知、成员移除重加或会话结束都会撤销旧的缺图发布资格；DATA 解码复用发送 token，页面只做查询。直接删除隔离会串服或把旧结果接到新会话；绕过版本门禁会让开发协议被稳定版策略误接纳；合并业务与目录生命周期会让目录失败错误中断正常玩法。 | `D-SESSION`、`D-SESSION-FAIL`、`D-WIRE`；**Essential**，身份空间隔离与局部失败直接对应产品要求。 | **Fact**：`VersionCompatibility`、`ClientModelSession.onServerHello`、`ClientSessionRuntime.beginConnection/businessSession/runIfCurrent`、`ServerModelService.runIfCurrent`、`ClientAssetTransfer`；`ModelSessionContractTest.differentDevelopmentProtocolVersionFailsOnlyTheModelSession` 断言失败仅限于模型会话局部。[session](../../architecture/network/implementation/transport-and-session.md)。版本门禁不新增协商状态或线协议字段；`BusinessSession` 也不新增线协议身份，发布与传输 ID 依然存在，不能把表现路径无代次的结论扩大成整个协议都无身份标识。 |
| MN-12 Typed admission 与业务局部 assembly | 每类请求各自维护自己的自然键、权限校验、范围覆盖校验和可选结束项。整份 descriptor 先完成校验，再在获取数据源之前建立对应的传输负责方。预览图只按 slot、model、container 发起请求，以唯一的 final range 动态定长并执行 16 MiB 与 128 MiB 限制及媒体解码；预览正常为空时返回 `ABSENT`。客户端按原始远端 Manifest 区分图片来源：独立图遇到确定性媒体拒绝可记缺图观察，其余失败不建立观察；icon 与 cover 保留 descriptor、hash 及 `UNAVAILABLE` 状态。管理查询、主目标分块与图片上传共用传输 ID 机制，但各自独立校验接纳权限；完整清单不自动赋予访问资格，上传的 header、接纳校验、offset 覆盖校验与严格提交只归属单次请求。直接删除校验会把半份或越权结果当成功；给预览图恢复 hash 校验则会平白新增缺乏依据的版本权威。 | `A-TYPED`、`D-CHUNKS`、`D-VALIDATE`、`D-ACCESS`；**Derived**。按类型划分的负责方用于承载不可省略的校验义务、获取窗口控制与图片弱关联语义。 | **Fact**：`ServerAssetTransfers.decodePresentation/validatePresentation`、`ClientAssetTransfer.PresentationChild/QueryChild/UploadChild`、`RenderTargetChunkPlan`、`ServerModelSession.Effect`；[资产传输](../../architecture/network/implementation/asset-transfer.md)。没有晚绑定 callback 负责方；构造异常、入队拒绝与接纳后的关闭仍归 MN-14。 |
| MN-13 仅超帧 action 的顺序 children | 只有完整 descriptor 超过单帧预算时，才顺序启动有限个子动作，父动作只汇总结果。取消父动作会阻止尚未启动的子动作，但不回滚此前已提交的精确缓存。直接删除父动作会丢失完整动作的汇总结果；一律拆成逐项发送则会成倍增加传输 ID 与结束状态开销。 | `A-FRAME-BUDGET`；**Derived**。 | **Fact**：`ClientAssetTransfer.MetadataAction/ModelAction`；[超帧理由](../../architecture/network/overview.md#超帧动作与子传输)。分片阈值是架构预算，不是 Minecraft 硬性单包上限；提高预算也不代表所有大动作都无需分片。 |
| MN-14 单一 accepted dispatch 与 range capability | 入队（enqueue）是整组数据包的所有权分界点。全局发送 worker 接管数据源、玩家 FIFO、发送游标（cursor）、限速与背压控制、重试和关闭职责，每次只构造当前有界帧。原始字节数组、供分块和独立图共用的字节 lease 以及文件区间，统一由单个 range packet 的三种 capability 负责读取和释放；入队被拒或构造失败时，仍由业务负责方关闭尚未转移的能力。直接删除这层统一接管会扩大内存驻留，并引发重复范围、重复结束、重复推进游标或双重关闭。 | `A-DISPATCH`、`D-ADMISSION`；**Derived**。 | **Fact**：`RangePacket`、`ResourceDispatchWorker.enqueue/visit`、`ServerAssetTransfers.submit`；[dispatch 理由](../../architecture/network/overview.md#传输接管与发送终态)。接纳时确定的授权结果不因后续撤权而重判；重试与游标不是第二套权限权威。反向图片上传游标由客户端 tick 按通道可写性与实际发送字节数限速推进，关闭时只撤销自身的字节引用。 |
| MN-16 当前选择、追踪发送与安装等待 | 服务端 capability 独占已提交的选择状态（committed selection），session 只保存请求顺序与连接资格。结构合法的新请求先推进顺序号；业务拒绝时保留旧选择并单播内置默认指派。状态发送模块只读借用游戏追踪视图（tracking），向观察者与玩家自身去重并按业务资格过滤，流量仍经原 dispatch FIFO。开始追踪与首次握手就绪共同补齐完整追踪信息；实体 flags 随追踪下发，server flags 归连接管理。LocalPlayer 忽略自身的选择和追踪回显，但仍消费实体增量与独立 flags。远端选择负责方维护零语义的稠密状态视图和安装等待队列；delta 段独立记录写集合，保护 `sync` 对未写字段的副作用。安装准备期固定编号映射，去掉了值 presence 标记与内部重复预检；连接负责方只记待消费总量。直接删除等待队列会丢失已接纳的 `sync` 事件，或打乱状态与事件的交错顺序。 | `A-REPORT`、`D-PLAYER`、`D-SERVER`、`D-TRACKING`、`D-SCRIPT`；**Derived**。方案取消了全业务会话广播、首次 FULL 和周期性 FULL，代价是宿主追踪适配层、一次 O(P) 初值扫描和有界暂存。上限为每选择 64 条、每连接 4096 条未消费 `sync`，超限丢新并计数，消费或清理时归还额度；选择失效、实体退休、会话失效或断连时清空，消费中途安装退休则结束剩余项。不增加 TTL、ACK 或网络重放。 | **Fact**：`CommittedSelection`、`PlayerStateHandler`、`ServerModelService`、`GameTrackingView`、`ClientRoamingSession`、`PendingRemoteReplay`、`EntityExpressionRuntime`；[玩家状态](../../architecture/network/player-state.md)。收包先整批校验；`sync` 分隔状态段，相邻写入合并，安装后串行消费且不与常规动画求值穿插。该状态与 MN-02 目录权威独立。真实 Forge 传输、实体生成顺序与成本证据见[支持状态](../../status/support-and-verification.md)。 |

| MN-31 配置整体接纳与目录分类 | Forge 执行纠错与保存前，先整体校验原始完整列表，把接纳副本与文件监听（watcher）隔离；游戏主循环负责方用当前有效列表对目录分类，并重新评估失去授权（grant）的选择。首次配置错误时封闭用户目录、保留 builtin；后续重载出错保留最近有效配置。直接删除接纳边界会把非法规则静默纠正为空，或混合新旧策略。 | `D-ACCESS`；**Derived**。 | **Fact**：`ServerConfigSpec`、`RestrictedModelPolicy`、`ServerModelService`；[配置与授权](../../architecture/model-management/sessions/overview.md)。路径与完整 ID glob 不进数据库；强制选择复用普通 grant，没有绕过授权的恢复状态。 |
| MN-32 启动目标汇合与一次性消费者 | 服务首次 tick 在无玩家时固定运行模式和账户，直接汇合 UUID 偏好查询与本地 Catalog 发布；获取前复核资格，执行一次离线 FULL 准备后持同一 lease 至结束条件并释放。直接删除汇合会漏掉先到输入或误把远端展示视图当本地事实；删除一次性边界会随目录重载或条件恢复反复触发冷准备。 | `A-STARTUP-WARMUP`；**Derived**。可选的无玩家预热是架构选择，增加一次查询、目录订阅和短期 lease；取消预热即可整体删除这些协调。 | **Fact**：`StartupModelWarmup`、`ClientModelService`；[目标、终态与成本](../../architecture/runtime/overview.md#启动模型一次性预热)及[接入](../../architecture/runtime/implementation/lifecycle-and-publication.md#启动预热的接入)。复用 MN-01/06/17/27/29/30，不新增缓存、线程池或持久化屏障；[验证方法与证据边界](../../verification/model-management.md#启动模型一次性预热)区分了策略、缓存组合与真实 GPU 发布的验证范围。 |
