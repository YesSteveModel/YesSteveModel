# 存储与状态验证缺口

当前职责见[机制](mechanisms.md)和[存储架构](../../architecture/model-management/storage/overview.md)。配置列表直接决定 `public` 与 `auth` 分类，强制选择复用普通授权（grant），不存在独立的绕过状态、策略库或未决产品问题。

## 运行与成本

以下几类运行成本目前还缺少代表性的吞吐或主循环实测结论：SQLite 连接的按需打开与复用、随条目和规则数增长的目录分类开销，以及缺少合法内存初值时主动选择等待 FULL 布局的延迟。此外，由于采用“先写完整文件、再短事务提交索引”的策略，会产生重复转换与孤儿文件，目前仅由 `converted` 的既定清理流程负责回收。业务 epoch 换代还会带来偏好空载、索引冷启动和旧文件占用，建立新索引时不会顺带清理旧缓存。

目前 Windows 真实 JNI、多 JVM、受控 I/O 故障和缓存重建各自覆盖了局部边界。至于真实 Forge 环境下的跨选择迟到消息、跨 UUID 与跨世界恢复、清除重选失败、完整授权组合，以及 Android 与 macOS 运行时、最低操作系统与指令集基线和断电恢复表现，均应按[当前状态](../../status/known-issues/model-management.md#目录存储与安装)分别判断，不能用单元测试、交叉构建或旧文件锁的证据去推断当前组合已经通过。
