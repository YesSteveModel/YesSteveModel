# 归约支点

本页记录由 NR 子系统主导的缓存、归档与未证实补偿机制的归约支点。

| 支点 | 最小改变 → 可减少部分 | 剩余义务、性能与可靠性成本及最小验证 |
|---|---|---|
| V-07 简化能力相关派生物 | 对常驻默认模型直接交付烘焙对象，或改为从磁盘读取后再做布局转换 → 可减少局部的“序列化再读取”步骤，以及按 SIMD 能力分裂的缓存目录。 | NR-05 的磁盘缓存和校验仍有其他消费者；该改动可能引入新的结果形态、schema 迁移或加载期重排开销，并不会让复杂度归零。改动成本中高；须先量化默认初始化转换开销与跨宽度输出等价性，且不改变公开作品身份。 |
| V-08 显式拥有 archive bytes | 把 `A-ARCHIVE` 的跨语言提取结果改为由调用方拥有独立副本 → “必须在下次读取前完成复制”的跨语言时间耦合即可消失。 | AP-01 的一致输入与独立捕获义务仍然存在；内存分配和复制可能只是从 Java 挪到 native，7z solid-block 解压缓存也仍需保留。改动成本中等；需验证连续两次读取后旧字节保持不变，并对比总复制次数与内存驻留后再判断净收益。 |
| V-09 精简未经证明的补偿 | 先核实 Q-02 的前提；只有确认已无独立价值后，才移除常驻加载线程与 `SystemAllocator` 分支。 | 线程加载、TLS 析构与跨线程完成关系必须分别验证。实现成本低到中，但取证成本可能较高；误删会直接引发 native 崩溃或内存可见性错误。至于历史混合机制 AN-08，另需结合 Q-06 的作品兼容结论判断，不能仅以“缺少历史记录”为由决定删除。 |

不建议为了“省去一次校验”而把 legacy 写当前容器的逻辑迁入 native：NR-13 的协议形态、投影保真以及 Java 侧 staging 重开分别拦截不同类别的故障，硬迁还会复制一套 Java 格式权威。

同帧计算调度与双输出路径由 [AN 归约支点](../java-animation-and-integration/reduction-pivots.md)主导；调整 Java 侧调度策略并不会自动取消 NR-08 和 NR-09 的输出区间隔离与任务完成同步义务。
