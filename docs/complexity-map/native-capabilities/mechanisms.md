# Native 能力层机制

本页是 NR 机制的唯一正文。子系统范围与阅读顺序见[总览](README.md)，证据口径和覆盖边界见[证据、覆盖与根依据](evidence-and-scope.md)。Java 侧顶点适配层归 AN，图片用途策略归 AP，共享模型 lease 与驻留管理归 MN，避免跨语言重复计数。模型语义与平台基线属于根约束；第三方 codec 算法、四区域业务规则和每条 SIMD 指令不因实现难读就单独拆成复杂度节点。

## 物理提取的帧发布

NR-06 的物理分支把求解器产出的 `BonePhysicsDelta` 交给现有层级提取器，最终姿态继续复用原有帧视图。求解可能先于绘制发布成功，因此 JNI 分别报告两者的结果。如果把提交条件合并为一个状态，绘制发布失败后的重试就可能重复步进。 [物理提交与绘制借用](../../architecture/rendering/implementation/frame-execution.md#物理提交与绘制借用)

## 机制

| ID / 机制 | 当前行为与直接删除的失败 | 上游原因 / 必要性 | 证据与边界 |
|---|---|---|---|
| NR-01 一次性 JNI 登记与绑定 | 加载器先在指定动态库中查询全局 ABI 标记；通过后再聚合静态 descriptor 并排序，拒绝空表或重复项并分组注册；状态只允许沿 `collecting → binding → bound/failed` 推进。直接删除校验或一次性约束会允许缺失或重复绑定；如果移除整个 registry，就必须改用其他入口绑定方案。 | `A-NATIVE`；**Derived**。固定 JNI ABI 必须完成入口绑定，但不强制使用静态 registrar。 | 行为 **Fact**：`NativeRuntime.load`、`JNI_OnLoad`、`BindEntry`、`EntryRegistry`；`JavaEntryTest` 覆盖空表、重复和一次性绑定断言。[加载边界](../../architecture/native-runtime/implementation/runtime-capabilities.md#加载与一次性绑定)。目前缺少静态 registrar 与代码生成注册表的独立历史对比。 |
| NR-02 Packed buffer 与 typed handle 交接 | 数组和 direct buffer 统一描述打包内存范围，native 侧按需借用或复制。Direct 顶点输出通过预留地址、字节容量与 anchor 交付原范围，Java 侧用 reachability fence 延续底层内存寿命直到同步 `Render` 返回；owning output 直接移交堆内存所有权，通用 opaque handle 包装按类型区分的共享 owner。直接删除现有协议会导致错读范围或类型，或破坏分配与释放的配对。 | `A-NATIVE`；**Derived**。跨语言范围校验与所有权交接义务不能随具体协议表示一起删除。 | **Fact**：`BufferInput/BufferOutput`、`CastOpaquePtr`、`NativeObject.adopt`、`NativeHeapBuffer.adopt`、`BufferArgument`；[JNI 内存](../../architecture/native-runtime/implementation/jni-and-memory.md)。Opaque handle 的接纳失败与 Cleaner 共用一次释放状态；buffer 先交付给 Storage，再按用途显式关闭或交给 GC owner 接管。类型检查不保证任意非空地址合法，reachability fence 也不提供关闭与使用之间的互斥；结果载体先由 native RAII 保护，Java 接纳失败时回滚；legacy payload 的多个独立 handle 共享同一底层内存；存储查询结果使用独立 owner，复制后立即关闭，交付异常保留已知提交事实或未知状态，且不泄漏临时 view。 |
| NR-03 Allocator 生命周期补偿 | 通过常驻加载线程（loader holder）加上局部 `SystemAllocator` 绕开 mimalloc 的 TLS 生命周期；直接删除后在当前环境下的失效条件尚未证实。 | `H-ALLOCATOR`；**Uncertain**。 | 行为和注释意图 **Fact**，当前必要性 **Hypothesis**。`NativeLibUtil.loadLibraryOnLifetimeThread`、`SystemAllocator`；[Q-02](open-questions.md#q-02)。存在历史注释不等于其前提已经消失。 |
| NR-04 能力相关 baked 热布局 | 节点按先序（preorder）排列、按骨骼组织 AoSoA 分组，物理分区与 lane 容量均服从选定的 SIMD 宽度。如果删除这层转换却保留现有读取器和渲染器，会直接错读分组边界。 | `A-SIMD`；**Derived**。逻辑分区本身不强制四套数组或 AoSoA 布局。 | **Fact**：`InitCpuInfo`、`BakeModel`、`BuildBoneHierarchy`、`CubeGroup`；[bake 分区](../../architecture/rendering/implementation/bake-and-partition.md)。这套热布局相对替代方案的实际收益尚未量化；[几何与可见面](../../architecture/rendering/overview.md#几何与可见面)归渲染设计，作品结果、输出等价与骨骼透明度作用范围仍受产品契约约束。 |
| NR-05 私有 serialized baked cache | 按 SIMD 能力生成的 payload 先经临时 DTO 组装运行时对象并重建分区 span 与累计信息，borrow 和 owning 路径共享同一套字段定义。完整的缓存目录、profile 与 hash 域隔离了内容、ABI、平台和指令集能力；Java 重开时先过开发版本门禁，再逐项校验宽度、结构、层级和容量。直接删除整个缓存仍可退回重烘焙，但如果只删隔离规则或共用稳定版 patch 命名空间，就会跨布局误复用。 | `A-BAKED-CACHE`、`A-SIMD`、`D-EXACT`；**Derived**。 | **Fact**：`BakedModelCache`、`BakedAnimationCache`、`VersionCompatibility`、`BakedModelView`、`BakedAssetView`、`SerializeBakedModel`、`ReadBakedModel/ReadForWidth`；[派生 cache 理由](../../architecture/model-management/storage/derived-artifacts.md)。版本门禁不扫描、迁移或共享旧 ABI 目录；常驻默认模型直接使用烘焙产物；普通未命中先交付完整内存候选，可选落盘由唯一存储域接纳；普通或 cache-only 命中则从单次校验取得的数据直接解码。共享 handle 只撤销引用，由 Cleaner 执行物理回收；native 容量与序列化上界增加了计价成本，但去掉了 Ready 等待和预检重读。完整 option 身份的接口前提见 [Q-03](open-questions.md#q-03)。 |
| NR-06 原地帧状态与 Java 借用 view | 整模提取与局部子树提取共享同一套算法定义和原始 indices；native 侧持有 poses、indices 与 scratch 内存，Java 侧直接借用地址。提取或发布任一环节失败都会撤销消费资格。直接删除所有权或原地复用边界，会导致消费错帧或访问已失效地址。 | `A-FRAME-REUSE`；**Derived**。固定的有效期约束直接来自当前原地复用方案。 | **Fact**：`ModelState::Extract/ExtractSubtree`、`NativeModelState` 与 JNI 入口；`ModelStateTest` 和 `FirstPersonLocalResultIntegrationTest` 覆盖局部层级、JNI 后置失败与异常原样回放。Java 侧必须在下一次 `extract`、`invalidate` 或 `close` 前完成消费，完整规则见[逐帧状态](../../architecture/rendering/implementation/frame-execution.md#输入输出与状态)。 |
| NR-07 可见工作计划缓存失效 | 整模与局部渲染共用同一套缓存失效条件：烘焙身份、worker 数量和完整可见骨骼序列均须匹配；如果仅有骨骼姿势（pose）变化，则复用原计划。如果只比较骨骼数量，会漏掉长度相同的成员替换（包括左右子树交替）。 | `A-PLAN-CACHE`；**Derived**。删除整层缓存仍可每帧重算，但只删失效条件会导致漏画或多画。 | **Fact**：`ModelState`、`RenderSchedule::Update`；`ModelStateTest.DetectsEqualSizedBoneIndexChange`、`LocalRangesRebuildEqualSizedSchedulesAndRecoverAfterFailure`。目前缺少缓存收益实测，不能因为失效逻辑正确就反推缓存必需。 |
| NR-08 固定 worker 输出区间 | 不可拆分的 `CubeGroup` 按分区展平，并为每个 worker 预分配互不重叠的顶点输出区间。直接删除区间隔离会让并行 worker 相互覆盖写入。 | `A-PARALLEL`；**Derived**。 | **Fact**：`RenderSchedule::Update`、`ScheduleTest.BuildsAllPartitionsAcrossWorkers`；[输出区间](../../architecture/rendering/implementation/vertex-output.md)。改成 append、prefix-sum 或 compact 只是迁移协调方式，并不能消除协调义务；由此派生的预留容量空洞清理单列为 NR-16。 |
| NR-09 Worker 依赖与完成协议 | 维护进程级 worker 池，由调用线程兼任 worker 0，通过 ready 与 completion 信号发布阶段进度；不同调度模式按需选择骨骼阶段或顶点阶段的等待策略，桌面端使用 spin 而 Android 端使用 wait。直接删除同步会让后续阶段消费未写完的状态。 | `A-PARALLEL`；**Derived**。并行组织方式可以调整，但阶段依赖顺序与成功交付不可省略。 | **Fact**：`DetermineRenderSchedulingMode`、`ParallelExecutor`、`WorkerReadyWaiter`、`renderer::Render`；[帧执行](../../architecture/rendering/implementation/frame-execution.md)。调度模式、worker 阈值、拓扑比例与特定 CPU 排除属于待测策略，不视为 Essential；主循环等待边界见 [Q-01](../java-animation-and-integration/open-questions.md#q-01)。 |
| NR-10 单 draw 透明暂存与重排 | 两个透明分区先把顶点写入 scratch 缓冲区和深度数组，再按当前 draw 的深度重排后复制到最终输出；阴影（shadow）路径可保持原始生成顺序。直接删除重排会退化成按生成或任务完成顺序混合，破坏透明渲染关系。 | `D-TRANSPARENCY` 与并行分散输出；**Derived**。受支持的透明语义属于独立产品义务，而 CPU 侧 scratch、中心深度排序键和复制属于实现选择。 | **Fact**：`TranslucentProxyBuffer`、`renderer::Render`；[透明边界](../../product-decisions/decisions/transparency-scope.md)、[顶点输出](../../architecture/rendering/implementation/vertex-output.md)。全局 scratch 引入了不可重入约束；现有排序不承诺所有高级透明场景都正确。 |
| NR-11 Archive 提取缓存借用 | Archive 包装层复用内部提取缓冲区，下一次读取其他文件可能覆盖前一次返回的 view。如果删掉缓冲区却保留借用协议，会产生悬空引用；如果调用方异步延迟消费却未提前复制，则会读到被覆盖的文件内容。 | `A-ARCHIVE`；**Derived**。 | 覆盖风险 **Fact**：`NativeArchive.getFile` 与 archive 包装层；[capture 与借用](../../architecture/asset-pipeline/implementation/conversion-and-export.md#raw-capture-与编译)。直接返回可复用 view 避免了逐次创建独立副本，支持“为了节省分配和复制”的 **Inference**；单纯从“简化生命周期”解释较弱，因为它反而增加了跨调用的时间耦合。历史选型依据与实际收益均未量化；7z solid-block 缓存则由解压算法本身独立决定。 |
| NR-12 Legacy 有界 buffer ingress 与流式解码 | Java 侧按观察到的文件长度把 v3 文件完整读入有界 direct buffer，遇到短读在输入边缘直接失败。Native 侧 `codec::ContainerReader` 借用这份只读视图，完成 checksum 校验、分块解密、dirty-zstd 还原和按需明文解压，`container::Reader` 同步拉取精确范围。直接删除 buffer 上限、短读检查或精确结尾校验，会让不完整输入进入格式解析。 | `A-LEGACY-READ`；**Derived**。保留源字节上限、格式校验和同步调用期内存保活；文件源稳定性由调用方负责，本层不承担平台文件锁、外部变更检测、分块 hash 基线或出口复验。 | **Fact**：`NativeLegacyImporter.invoke`、`ContainerReader`、`container::Decode`、`legacy::Import`；`LegacyEnvelopeTest` 覆盖来源、格式和预算断言。[输入契约与理由](../../architecture/asset-pipeline/implementation/conversion-and-export.md#legacy-envelope-的输入契约)；native 调用不保存全局 importer 状态，也不创建线程。 |
| NR-13 Legacy typed projection 与整体结果 owner | `conversion` 按当前 schema 产出 `ImportResult`，其中执行字段只携带源程序文本（source Program），大图片和音频进入独立 payload。胶水层负责编码 descriptor，并由单个 result owner 统一保活全部 direct buffer。直接删除会错接 payload、丢失转换诊断或失去内存保活；如果恢复第二套 legacy Proto 或长期保留 legacy 运行时，则会复制一套格式权威。 | `A-LEGACY-PROJECTION`、`A-ONE-ARTIFACT`、`D-MIGRATION`；**Derived**。单向兼容与内容保留是根义务。 | **Fact**：`conversion::Convert`、`ProjectedPayloadCount`、`ResultOwner`、`NewSuccessResult`、`SourceProgram`；[转换出口](../../architecture/asset-pipeline/implementation/conversion-and-export.md#历史输入的单向投影)。Java 侧的 payload 校验与当前容器 staging 重开另归 AP-06，不与 native 的 result owner 重复计数。 |
| NR-14 统一 Ogg 时间轴、不可变 checkpoint 与独占 Opus decoder | 严格的 page 与 packet 读取器统一了音频检查（inspect）、R/T 生成、legacy 分类和增量播放四条路径的时间轴。首块解码排空（drain）后，深拷贝 codec 与 parser 状态及未完成 packet 生成不可变 checkpoint；共享 checkpoint 通过私有 handle owner 回收，每次恢复都创建独立的 decoder 实例。直接删除状态复制会导致前缀与尾部接缝重复或漏帧；把共享对象当成活跃 decoder 使用则会引发游标和关闭竞争。内存计价、接纳流程以及按源声道变化的状态体积增加了跨语言协调成本。 | `D-SOUND`、`A-NATIVE`、`A-AUDIO-RETENTION`；**Derived**。精确媒体输出与清晰所有权是义务；如果不再需要前缀复用，可连同 checkpoint 与 restore 一并删除。 | **Fact**：`InspectAudio`、`NormalizeAudio`、`OpusAudioCheckpoint`、`OpusDecoder.Checkpoint`、`PlaybackAudioStream`；[native 能力](../../architecture/native-runtime/implementation/runtime-capabilities.md#能力分工)与[checkpoint 契约](../../architecture/native-runtime/implementation/jni-and-memory.md#音频-checkpoint)。行为断言已覆盖接缝对齐、独立恢复与失败交接；构建、codec 与设备覆盖范围见[支持状态](../../status/support-and-verification.md)。 |
| NR-15 JNI 错误收口 | 通用入口 thunk 把 C++ 异常和错误码统一映射为入口失败值，Java 侧先检查并解释后再推进后续逻辑。设备默认配置查询把“未知或失败”与“合法低配”明确区分，结果仅由 Java 缓存一次。直接删除错误边界会让调用方把失败值误当正常结果，或失去跨 ABI 的异常隔离。 | `C-JNI`、`D-FAIL`；**Essential**。具体回退编码可调整，但失败不提交的义务不可省；设备查询另承担平台 API 调用与进程级默认缓存成本。 | **Fact**：JNI 入口包装层、`JavaEntryTest` 异常回退断言；[失败如何返回](../../architecture/native-runtime/implementation/runtime-capabilities.md#失败如何返回)与[设备配置默认](../../architecture/native-runtime/implementation/runtime-capabilities.md#设备配置默认)。查询得到未知结果后不会在后台重试恢复；设备总拓扑也不复用渲染调度的核心过滤。通用回退编码不保证保留完整的 native 错误子类；legacy 导入的结构化 response 有其独立用途。 |
| NR-16 预留容量空洞清理 | 剔除之后未写入的预留顶点容量会被清零，透明缓冲区空位则填入无效排序键（invalid key）。直接删除清理步骤会把上一轮残留的缓冲区字节误当成本帧顶点提交。 | NR-08；**Derived**，仅服务于“提交预留区间而非紧凑实际长度”的策略。 | **Fact**：native 顶点输出与 `TranslucentProxyBuffer`；[顶点输出](../../architecture/rendering/implementation/vertex-output.md)。只有取消按带空洞区间提交，这项补偿才会失去存在理由；并行区间隔离和透明重排仍需保留。 |
| NR-17 Legacy 图片的解码期表示归约 | 解码器在读出每个图片字段后立即校验，并按 texture、gui、avatar、icon、thumbnail 五类用途准备目标编码：RGBA32 直接移动后编码，PNG 先解码再重新编码，合法的 JPEG、WebP、AVIF 等格式直接复用；编码结果必须通过 round-trip 校验才能进入模型对象。转换器移交已准备好的字节，同一 blob 源再次出现时复用首次编码结果，并禁止跨用途复用。直接删除解码期归约会让整份 `LegacyModel` 长期滞留未压缩的 RGBA32 或重复编码；删除用途校验或 round-trip 门禁则会交付错误格式的图片。 | `A-LEGACY-READ`、`A-IMAGE`；**Derived**。用于在完整模型驻留内存的前提下控制峰值内存和重复编码；若改成事件流式转换可调整执行时点，但用途语义与目标格式校验仍需保留。 | **Fact**：`ParseImage`、`PrepareImage`、`ValidatePreparedImage`、`ImageCollector`、`TakePreparedImage`；[历史输入投影](../../architecture/asset-pipeline/implementation/conversion-and-export.md#legacy-envelope-的输入契约)。编解码性能、阈值及跨平台视觉差异见 [Q-04](../java-assets-and-presentation/open-questions.md#q-04)。 |
