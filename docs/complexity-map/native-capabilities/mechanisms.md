# Native 能力层机制

本页是 NR 机制的唯一正文；子系统范围与阅读顺序见[总览](README.md)，证据口径和覆盖边界见[证据、覆盖与根依据](evidence-and-scope.md)。Java 顶点 adapter 归 AN，图片用途策略归 AP，共享模型 lease/residency 归 MN，避免跨语言重复计数。模型语义与平台目标是根约束；codec 算法、四区域业务规则和每条 SIMD 指令不因难读而单独成为复杂度节点。

## 机制

| ID / 机制 | 当前行为与直接删除的失败 | 上游原因 / 必要性 | 证据与边界 |
|---|---|---|---|
| NR-01 一次性 JNI 登记与绑定 | 加载器先在指定库查询全局 ABI 标记；通过后静态 descriptor 聚合并排序、拒绝空表/重复，分组注册；只允许 collecting→binding→bound/failed。删除校验或一次性约束会允许缺失/重复绑定，移除整个 registry 则须替换入口绑定方式。 | `A-NATIVE`；**Derived**。固定 JNI ABI 需要绑定，但不强制静态 registrar。 | 行为 **Fact**：`NativeRuntime.load`、`JNI_OnLoad`、`BindEntry`、`EntryRegistry`；`JavaEntryTest` 的空表、重复和一次绑定断言。[加载边界](../../architecture/native-runtime/implementation/runtime-capabilities.md#加载与一次性绑定)。未找到静态 registrar 相对生成表的独立历史比较。 |
| NR-02 Packed buffer 与 typed handle 交接 | Array/direct 描述打包范围，native 借用或复制；owning output 转移 allocation，通用 opaque handle 包装 typed shared owner。删除既有协议会错读范围/类型或失去释放配对。 | `A-NATIVE`；**Derived**。跨语言范围与 ownership 义务不能随表示一起删除。 | **Fact**：`BufferInput/BufferOutput`、`CastOpaquePtr`、`NativeObject.adopt`、`NativeHeapBuffer.adopt`、`BufferArgument`；[JNI 内存](../../architecture/native-runtime/implementation/jni-and-memory.md)。Opaque handle 的 adoption 失败与 Cleaner 共用一次释放状态；buffer 先交付 Storage，再按用途显式关闭或由 GC owner 接管。类型检查不证明任意非空地址有效，reachability fence 不提供 close/use 互斥；结果载体先由 native RAII 保护，Java adoption 失败回滚；legacy payload 的独立 handle 共享 backing。 |
| NR-03 Allocator 生命周期补偿 | 常驻 loader holder 加部分 `SystemAllocator` 绕过 mimalloc TLS；直接删除的当前失效条件未证明。 | `H-ALLOCATOR`；**Uncertain**。 | 行为和注释意图 **Fact**，当前必要性 **Hypothesis**。`NativeLibUtil.loadLibraryOnLifetimeThread`、`SystemAllocator`；[Q-02](open-questions.md#q-02)。有历史意图不等于前提已消失。 |
| NR-04 能力相关 baked 热布局 | Preorder、按骨骼 AoSoA group、物理分区与 lane 容量服从选定 SIMD；删除转换而保持 reader/render 会错误解释组范围。 | `A-SIMD`；**Derived**。逻辑分区不规定四套数组或 AoSoA。 | **Fact**：`InitCpuInfo`、`BakeModel`、`BuildBoneHierarchy`、`CubeGroup`；[bake 分区](../../architecture/rendering/implementation/bake-and-partition.md)。具体布局优于替代方案的收益未量化；[几何与可见面](../../architecture/rendering/overview.md#几何与可见面)归渲染设计，作品结果、输出等价与骨骼透明度作用范围仍受产品契约约束。 |
| NR-05 私有 serialized baked cache | 能力相关 payload 经临时 DTO 组装运行时对象并重建分区 span / 累计信息，borrow/owning 共享字段定义；完整 cache ABI 的目录/profile/hash domain 隔离 content、ABI、平台和能力，Java 重开时先经开发版本门禁，再验证宽度、结构、层级和容量。删除 cache 可重烘焙；只删隔离或共享 stable patch namespace 会跨布局复用。 | `A-BAKED-CACHE`、`A-SIMD`、`D-EXACT`；**Derived**。 | **Fact**：`BakedModelCache`、`BakedAnimationCache`、`VersionCompatibility`、`BakedModelView`、`BakedAssetView`、`SerializeBakedModel`、`ReadBakedModel/ReadForWidth`；[派生 cache 理由](../../architecture/model-management/storage/derived-artifacts.md)。门禁不扫描、迁移或共享旧 ABI 目录；Resident 直接使用 bake 模型；普通 miss 先交付完整内存候选，可选写入由唯一存储域接纳；普通/cache-only hit 从一次验证取得的数据直接 decode。共享 handle 只撤引用，Cleaner 物理回收；native 容量/序列化上界增加计价成本，去掉 Ready 等待与预检重读。完整 option 身份的接口前提见 [Q-03](open-questions.md#q-03)。 |
| NR-06 原地帧状态与 Java 借用 view | 整模与局部根共享算法定义和原始 indices；native owns poses、indices 与 scratch，Java 借用地址。提取与发布任一失败均撤销消费资格。删除 owner/复用边界会消费错帧或失效地址。 | `A-FRAME-REUSE`；**Derived**。固定有效期义务来自当前原地复用选择。 | **Fact**：`ModelState::Extract/ExtractSubtree`、`NativeModelState` 与 JNI entry；`ModelStateTest`、`FirstPersonLocalResultIntegrationTest` 覆盖局部层级、JNI 后置失败与原样回放异常。下次 extract/invalidate/close 前消费；规则唯一见[逐帧状态](../../architecture/rendering/implementation/frame-execution.md#输入输出与状态)。 |
| NR-07 可见工作计划缓存失效 | 整模与局部结果共用 baked identity、worker 数和完整可见骨骼序列的失效条件；只有 pose 改变则复用。只比较数量会漏掉等长成员替换，包括左右子树交替。 | `A-PLAN-CACHE`；**Derived**。删除整个缓存可每帧重算，删除失效条件会漏画/多画。 | **Fact**：`ModelState`、`RenderSchedule::Update`；`ModelStateTest.DetectsEqualSizedBoneIndexChange`、`LocalRangesRebuildEqualSizedSchedulesAndRecoverAfterFailure`。缓存收益缺测量，不能由正确失效证明缓存必需。 |
| NR-08 固定 worker 输出区间 | 不可拆分 CubeGroup 按分区展平，预分配互不重叠的 vertex ranges；直接删除隔离会使 worker 相互覆盖。 | `A-PARALLEL`；**Derived**。 | **Fact**：`RenderSchedule::Update`、`ScheduleTest.BuildsAllPartitionsAcrossWorkers`；[输出区间](../../architecture/rendering/implementation/vertex-output.md)。改 append/prefix-sum/compact 只是迁移协调义务；容量空洞的附属补偿单列 NR-16。 |
| NR-09 Worker 依赖与完成协议 | 进程级 worker 池、caller worker 0、ready/completion 发布；不同模式选择骨骼阶段/顶点阶段的等待，桌面 spin 与 Android wait 不同。删同步会消费未完成状态。 | `A-PARALLEL`；**Derived**。并行方式可改变，依赖顺序与成功交付不可省略。 | **Fact**：`DetermineRenderSchedulingMode`、`ParallelExecutor`、`WorkerReadyWaiter`、`renderer::Render`；[帧执行](../../architecture/rendering/implementation/frame-execution.md)。模式、worker 阈值、拓扑比例与特定 CPU 排除属于待测策略，未单独提升为 Essential；等待边界见 [Q-01](../java-animation-and-integration/open-questions.md#q-01)。 |
| NR-10 单 draw 透明暂存与重排 | 两透明分区写 scratch/depth，按当前 draw 重排后复制；shadow 路径可保持生成顺序。删除后会按生成/任务顺序混合，不能保证同样的透明关系。 | `D-TRANSPARENCY` 与分散输出；**Derived**。受支持透明语义是独立义务，CPU scratch/中心深度 key/复制是实现选择。 | **Fact**：`TranslucentProxyBuffer`、`renderer::Render`；[透明边界](../../product-decisions/decisions/transparency-scope.md)、[顶点输出](../../architecture/rendering/implementation/vertex-output.md)。全局 scratch 引入不可重入协调；排序存在不证明所有高级透明场景正确。 |
| NR-11 Archive 提取缓存借用 | Archive wrapper 复用提取缓存，下次取文件可覆盖旧 view；删除 cache 而保留借用协议会悬空，异步延迟消费而不复制会混淆文件内容。 | `A-ARCHIVE`；**Derived**。 | 覆盖风险 **Fact**：`NativeArchive.getFile` 与 archive wrapper；[capture 与借用](../../architecture/asset-pipeline/implementation/conversion-and-export.md#raw-capture-与编译)。直接返回可复用 view 避免逐次创建 owning 副本，支持节省分配/复制的 **Inference**；单纯简化生命周期的解释较弱，因为它反而增加调用间时间耦合。历史选择与实际收益未量化；7z solid-block 缓存有解压算法的独立依据。 |
| NR-12 Legacy 有界 buffer ingress 与流式解码 | Java 按观察长度把 v3 文件完整读入有界 direct buffer，短读在输入边缘失败；native `codec::ContainerReader` 借用该只读视图，完成 checksum、分块解密、dirty-zstd 还原和按需明文解压，`container::Reader` 同步拉取精确范围。删除 buffer 上限、短读或 exact-finish 检查会让不完整输入进入格式解释。 | `A-LEGACY-READ`；**Derived**。保留源字节上限、格式验证和同步调用期保活；来源稳定性由调用方负责，不承担平台锁、变化检测、分块 hash 基线或出口复验。 | **Fact**：`NativeLegacyImporter.invoke`、`ContainerReader`、`container::Decode`、`legacy::Import`；`LegacyEnvelopeTest` 的来源、格式和预算断言。[输入契约与理由](../../architecture/asset-pipeline/implementation/conversion-and-export.md#legacy-envelope-的输入契约)；native 调用无 importer 全局状态且不创建线程。 |
| NR-13 Legacy typed projection 与整体结果 owner | `conversion` 以当前 schema 交付 `ImportResult`，执行字段只携带 source Program；大图片和音频进入 payload。Library glue 编码 descriptor，一个 result owner 保活全部 direct buffer。删除会错接 payload、丢失投影诊断或失去 owner；恢复第二套 legacy Proto 或长期 legacy runtime 则复制 authority。 | `A-LEGACY-PROJECTION`、`A-ONE-ARTIFACT`、`D-MIGRATION`；**Derived**。单向兼容和内容保留是根义务。 | **Fact**：`conversion::Convert`、`ProjectedPayloadCount`、`ResultOwner`、`NewSuccessResult`、`SourceProgram`；[转换出口](../../architecture/asset-pipeline/implementation/conversion-and-export.md#历史输入的单向投影)。Java payload 校验与当前容器 staging/重开另归 AP-06，不与 native result owner 重复计数。 |
| NR-14 统一 Ogg 时间轴、不可变 checkpoint 与独占 Opus decoder | 严格 page/packet reader 统一 inspect、R/T 生成、legacy 分类与增量播放时间轴。首块 drain 后深拷贝 codec/parser 状态与未完成 packet；共享 checkpoint 通过私有 handle owner 回收，每次 restore 创建独立 decoder。删除状态复制会让前缀与尾部重复或漏帧；把共享值当活动 decoder 会产生 cursor/关闭竞争。计价、adoption 和源声道 state 大小增加跨语言协调成本。 | `D-SOUND`、`A-NATIVE`、`A-AUDIO-RETENTION`；**Derived**。精确媒体输出和 ownership 是义务；前缀复用不再需要时，可连同 checkpoint/restore 删除。 | **Fact**：`InspectAudio`、`NormalizeAudio`、`OpusAudioCheckpoint`、`OpusDecoder.Checkpoint`、`PlaybackAudioStream`；[native 能力](../../architecture/native-runtime/implementation/runtime-capabilities.md#能力分工)与[checkpoint 契约](../../architecture/native-runtime/implementation/jni-and-memory.md#音频-checkpoint)。行为断言覆盖接缝、独立恢复和失败交接；构建、codec 与设备范围见[支持状态](../../status/support-and-verification.md)。 |
| NR-15 JNI 错误收口 | 通用 entry thunk 将 C++ exception/status 映射为入口失败值，Java 解释后才推进结果；设备默认将未知/失败与合法低配区分，只由 Java 缓存一次结果。删除错误边界会让调用者误认失败值或失去跨 ABI 异常隔离。 | `C-JNI`、`D-FAIL`；**Essential**。具体 fallback 编码可变，失败不提交的义务独立；设备查询承担平台 API 与进程默认缓存成本。 | **Fact**：JNI entry wrapper、`JavaEntryTest` 异常 fallback；[失败如何返回](../../architecture/native-runtime/implementation/runtime-capabilities.md#失败如何返回)与[设备配置默认](../../architecture/native-runtime/implementation/runtime-capabilities.md#设备配置默认)。未知结果不会后台恢复；设备总拓扑不复用调度过滤。通用 fallback 不保证保留完整 native 错误类别；legacy 的结构化 response 有独立用途。 |
| NR-16 预留容量空洞清理 | 剔除后未写的固定容量清零，透明空位用 invalid key；删除后可将上一轮 buffer bytes 当成顶点提交。 | NR-08；**Derived**，只为“提交预留区间而非紧凑实际长度”服务。 | **Fact**：native vertex 输出与 `TranslucentProxyBuffer`；[顶点输出](../../architecture/rendering/implementation/vertex-output.md)。若取消空洞区间提交，此补偿才失去理由；并行安全和透明重排仍保留。 |
| NR-17 Legacy 图片的解码期表示归约 | Decoder 在每个图片字段读出后立即校验并按 texture/gui/avatar/icon/thumbnail 角色准备目标编码：RGBA32 被移动后编码，PNG 被解码后编码，合法 JPEG/WebP/AVIF 等表示直接复用；输出 round-trip 验证后才进入模型对象。Projector 移交 prepared bytes，同一 blob 源再次出现时复用首次编码结果并拒绝跨角色复用。删除提前归约会让整份 `LegacyModel` 长期保留 RGBA32 或重复编码，删除角色/round-trip 门禁会交付错误表示。 | `A-LEGACY-READ`、`A-IMAGE`；**Derived**。在完整模型物化的前提下控制峰值表示和重复工作；改为事件式投影可替换时点，但用途语义与目标表示验证仍保留。 | **Fact**：`ParseImage`、`PrepareImage`、`ValidatePreparedImage`、`ImageCollector`、`TakePreparedImage`；[历史输入投影](../../architecture/asset-pipeline/implementation/conversion-and-export.md#legacy-envelope-的输入契约)。编解码性能、阈值与跨平台视觉结果仍见 [Q-04](../java-assets-and-presentation/open-questions.md#q-04)。 |
