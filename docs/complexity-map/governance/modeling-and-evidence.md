# 建模、证据与计数口径

本页只定义所有子系统共用的分类、证据强度、节点口径和全局验证边界；各子系统的实际覆盖、根键、关系投影与缺口由其本地页面维护。

## 分类与证据

`Essential` = 当前业务/外部契约直接要求的义务；`Derived` = 依赖可修改上游选择的现存机制；`Historical` = 已证实原前提消失但机制仍在；`Uncertain` = 必要性未闭合。当前图没有足够证据标 Historical。旧注释、未找到消费者或不符合新契约，都不等价于已证实可删。

`Fact` = 引用材料直接支持该条结论；`Inference` = 强支持但缺直接记录，必须保留支持事实及更弱的竞争解释；`Hypothesis` = 多种解释尚未排除，保留归约影响与最小验证入口。三者附着于具体结论和边，与必要性独立。架构规则只能证明规定，源码可证明当前选择、必要条件或删除失败，都不能证明未记录的历史动机。各机制页的“删除失败”均在保持其他设计不变的反事实下成立；替换上游可能让部分失败条件不再可达。

节点按语义建模：D/C 是产品或外部根约束，A 是内部选择，P 是问题/失败机会，AP/MN/AN/NR 是机制，H 是待验证根。类、方法、文件和字段仅为证据导航；同一语义跨实现不重复计数。机制簇不参与计数；必要性、上游前提或退出条件不同的成员保留独立记录。`Essential` 保护的是已说明的义务，不把当前协议、缓存或状态表示固化为唯一实现。

## 全局验证边界

全图记录 62 个生产机制。计数描述文档粒度，不表示系统变复杂或已穷尽所有机制。地图复用已有机制证据，针对变化和缺口核验当前代码；未逐条重新审计全部实现。CodeGraph/GitNexus 只生成结构候选，不确定分派、overload 歧义与 `.inc` 缺边不能补因果。本图更新不以文档检查替代游戏、Gradle/CMake 或性能验收；链接、Mermaid、ID/关系与计数是静态证据，机制页引用的测试结果仍只覆盖各自观察边界。

Java 机制页引用测试作为可定位的行为断言，未把测试名称或静态调用关系当成运行通过的证明。完整格式 golden、真实 GUI 反复翻页与关闭、GPU texture 回收和实机模型外观仍受[支持与验证边界](../../status/support-and-verification.md)限制。

[Mock 验证设施](../../verification/model-management.md)的进程监督、物理 classpath 隔离与证据汇总是测试协调，不计为生产机制；通过某一层也不自动闭合其他层的未验项。精确读取实例、converted consumer/prune 及页面 batch 失败收敛分别展开于 MN-05、MN-24 与 AP-04，不另按验证场景新增节点。

关系类型与按需加载规则见[关系登记入口](relationship-register.md)；Fact 边由四个子系统关系页和[跨子系统关系](cross-subsystem-relations.md)唯一维护，全局计数见[高扇出候选](global-fanout.md)，根键解释见[根依据总表](root-register.md)。
