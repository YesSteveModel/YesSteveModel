# 归约支点

本页记录由 AN 子系统主导的调度、姿态、输出和扩展归约支点；涉及其他子系统的后果可沿文末链接继续追踪。

| 支点 | 最小改变 → 可减少部分 | 剩余义务、成本与最小验证 |
|---|---|---|
| V-02 同帧计算调度 | 主线程生命周期与对应 `get` 已替代普通路径上的通用 runtime barrier，单实体提前消费不会阻塞其他实体并行，调用末尾统一 drain。在此基础上继续对比 inline、当前异步和更少 native worker 的模式，可评估是否缩减 AN-02 等待以及 NR-09 的 ready 与模式组合。 | 不能直接删掉 `get`；实体隔离、动作次数、过期结果、lease、固定输出和透明排序义务仍在，局部绘制借用、编译 inbox 与共享资源同步也各自有独立责任。真实宿主与低核数成本尚未验证；若改为多帧结果槽，会增加状态并改变延迟；若改为 tick 采样加插值，则需重新裁决采样契约。 |
| V-05 分离可复用姿态与 draw 参数 | 缩小 `A-AN-02` 中会被不同 pass 改写的共享输入，可减少 AN-04 的姿态恢复条件及 context 污染；明确动作提交窗口也能缩减 AN-05 中散落的门禁。 | AN-01 的实体历史与 AN-05 的动作次数义务不会消失，不同 context 间真实的姿态差异也必须保持。属于中高成本改造，需用 `level → shadow → inventory → level`、相机变化、隐藏 locator 以及 transition、defer 与 sync 样本验证；仅套一层包装不算归约。 |
| V-06 统一消费者或计算输出 | 调整 `A-NATIVE` 的交接方式，或只保留一种顶点输出桥，可去掉部分 AN-11 的适配分支。 | NR-01、02、15 仍有 codec、archive 与 legacy 消费者，AN-12 的宿主输出完整性也独立存在；删 direct 会带来吞吐与材质代价，删 fallback 会缩小支持的 consumer 范围。该方向风险高且缺少收益数据，当前不优先，动手前需先对照两条路径的几何、法线、透明与材质结果。 |
| V-11 收窄扩展检查 | 当真实扩展样本证明更窄的检查面已足够时，可缩减 AN-09。 | AN-10 的可选联动降级仍有独立责任。属于中高成本改造，动手前需先检查真实 API 变动样本及加载和注册失败矩阵。 |

V-02 与 V-06 会同时影响 native worker 和输出能力，但实体调度与宿主 consumer 仍归 AN 侧解释；NR 侧的能力布局与并行区间不能随 Java 路径调整而自动删除。关于 allocator 与 fence 的联合核实，见 [NR 归约支点](../native-capabilities/reduction-pivots.md)。
