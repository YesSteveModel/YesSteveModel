## 玩家骨骼物理

- **AN-01 的安装所有权**。`AnimationSession` 持有 `PlayerPhysicsSession`，每份含物理的玩家安装独立拥有原生世界。兼容换纹理沿用会话，结束安装会关闭世界。把世界挂到共享资产上会让同一模型的玩家共享速度和接触历史。把世界挂到单次绘制上则会丢失跨帧历史。 [实体安装生命周期](../../architecture/animation/entity-lifecycle.md#模型使用与完整安装)
- **AN-02 的跨实体输入**。并行调度把载具状态交给载具自己的 worker，骑手仍需要匹配的倾角和竖直偏移。调用级预采样为提取和绘制固定同一份输入，代价是倾角可落后载具本轮求值一帧。 [实体根与载具预采样](../../architecture/rendering/implementation/frame-execution.md#实体根与载具预采样)
- **AN-04 的观察隔离**。多 pass 共用物理历史时，正文独占主槽，先到的观察路径使用独立快照求值并还原共享骨属性。代际校验使已经准备但尚未绘制的输出随样本失效。如果移除主槽隔离，观察结果会改变下次主轮的骨枢轴查询输入。 [骨骼物理的主槽与观察槽](../../architecture/rendering/implementation/frame-execution.md#骨骼物理的主槽与观察槽) · [物理提交与绘制借用](../../architecture/rendering/implementation/frame-execution.md#物理提交与绘制借用)

| AN-01 实体私有求值状态 | 同一目标的不可变 module、catalog、绑定与模型资源可以共享，而每个 owner 独占 holder、instance、controller、random、physics、deferred、Roaming 与骨骼状态。GUI 卡片另外持有私有主体。唯一的世界角色在正常主轮成功后一次性发布不可变完成样本，GUI、第一人称、watch 与 defer 不参与发布。真实使用结束时会封口并清空 Entity 槽，连续换模则保留前值；远端玩家输入会被复制为不可变快照。源槽可持有 Entity，但不持有目标组件、runtime 或 lease，源结束时清槽。主线程先固定本帧输入，owner 捕获私有的类型化草稿，任务在同一份输入下完整绑定并求值，临时主体值在任务退出前恢复，绘制阶段只消费准备结果。实体本身只保存 selection target、操作与实际使用情况，派生候选不另建 assignment。`LocalPlayer` 会话只保留一份恢复快照，临时 runtime 不建立恢复资格；主线程按精确对应的安装接纳 Body 变化，`endUse` 在封口前完成最终接纳。Roaming 按模块局部编号读写必有值数组，producer 的 dirty 列表有界；变量名只在布局配对与命名持久化边界出现，去掉了 roaming presence 与逐批字符串回转。两侧交接完成后才投影到精确对应的 arm 或 vehicle，双手与背景仍共用第一人称时间线。如果合并可变状态，不同 owner 的动画历史会互相污染；如果把恢复数据绑在具体安装上，卸载或迟到恢复时会丢失值。 | `D-ENTITY`；**Essential** 保护的是实例隔离本身，不要求通用的 runtime 锁。GUI 输入快照与临时主体作用域引入了帧输入捕获、装备复制与恢复成本；只有当 owner 能直接消费等价的不可变输入并保持绑定、求值与绘制语义时，才可删除这些桥接状态。 | **Fact**：`ClientRoamingSession`、`EntityExpressionRuntime`、`EntityExecutionLifecycle`、`AnimatableEntity`、`AnimationProcessor`，以及[实体 owner](../../architecture/animation/implementation/entity-and-frame-state.md#实体级所有权)与[Roaming](../../architecture/animation/implementation/state-inputs-and-sync.md#roaming)。Retire 永久终止 owner，reset 与 reload 保留再次使用资格。兼容纹理保留原操作及既有历史；同值显式重选会建立新操作并初始化私有状态，新内容仅承接位置历史。Cleaner 只兜底独立 lease；GUI 固定输入测试不替代真实宿主与可选扩展 provider 的运行观测。 |
| AN-02 异步实体任务的串行与汇合 | 主线程为每个 owner 保存原待交接任务，并交由调度器直接 `execute`。实体渲染等待时可以通过队列 `remove` 唯一领取并运行原任务，其他等待方不会领取。对应的 `get` 覆盖完整更新与 `finally` 清理，全部结束后才重新开放状态更新。GUI 的完整绑定与求值使用同一实体及 expression runtime 的精确执行许可，任务尚未 join 前实例不会对外开放。页面先提交后台卡片，再执行首卡并立即注册首卡结果，待全部已接纳任务交接完成后再发布其余结果。无论遇到提交拒绝、普通失败还是线程中断，都不会跳过 drain；关闭时先封口，实例和未交付能力在交接完成后统一清理。其他 owner 仍保留各自的调度和安装入口。如果删掉完整交接，求值、Extract、draw、重绑或关闭操作就会并发重叠。 | `A-AN-01`；**Derived**。成本包括精确执行许可、帧内任务收尾、`finally` drain 与失败聚合；单实体串行顺序和资源关闭属于独立义务，但具体调度方式可替换。只要生命周期层能直接提供等价的独占执行范围，许可表示即可归约；只有当绑定与求值不再跨线程借用可变实例时，才能删掉临时执行权交接，但结果与能力仍须完整收尾。 | **Fact**：`AnimationParallelTicker`、`EntityExecutionLifecycle`、`EntityExpressionRuntime`、`CatalogPageFrame`、`GuiFrameTasks`，以及[任务交接](../../architecture/rendering/implementation/frame-execution.md#任务发布与并发边界)。局部绘制借用、独立编译 inbox 交付与共享资源同步并不保护普通的实体访问。真实 Forge 接线、可选扩展 provider 以及完整帧成本仍需运行证据，见 [Q-01](open-questions.md#q-01)。 |
| AN-03 跳过求值时维持逻辑时间 | Owner 独占已接纳的 `tick` 与 `time` 两条基线，首次组件采样跨度为零；限频恢复时一次性消费累计跨度，而单纯的观察与姿态复用不会推进基线。如果把每次执行都当成固定一步，被降频的实体就会减速或重复触发动作。 | `A-AN-03`；**Derived**。降频补偿状态依赖当前的限频选择，但实际呈现时间推进与“重复观察不重复动作”仍有独立义务。 | 行为与时间关系属 **Fact**。按距离和可见性直接减少求值次数，支撑“降低 CPU 工作量”的 **Inference**（仅靠修正动作语义不足以解释为何按距离降频）。第一人称手部的仅动画更新复用同一逻辑时间与限频规则，重复观察不新建 token；背景完全不调用求值。具体阈值的选取理由仍属 **Hypothesis**，尚无对比测量。入口为 `AnimatableEntity`，整体表现与因果保持核验见 [O-07](open-questions.md#其他实现边界)。 |
| AN-04 多 pass 共用历史的输出分离与姿态恢复 | 常规世界渲染复用 canonical 输出，其他 RenderContext 按需重新求值，coded 动画造成的姿态修改在进入后续 pass 前恢复。第一人称下同一 owner 持有三份独立的持久输出，由准备资格与实际有效性共同门控帧内重复消费，并跨帧保留 schedule。背景声明的初始数组绑定到实际的 target 与 `GeoModel`，与活跃属性分开管理，原地换模时也会重建。如果删掉这些协调，某个 pass 中的头部隐藏或姿态修改会污染另一个 pass，背景也可能误用动画姿态或旧资源。 | `A-AN-02`；**Derived**。正因为选择了多个 pass 共用 controller 历史和骨骼输入，才需要跨 pass 的姿态恢复。 | **Fact**：`AnimatableEntity.update`、`AnimatableEntity.computePose`、`PlayerAnimatableCapability.recoverLastCodedAnimation`，以及[输出与 context](../../architecture/animation/implementation/entity-and-frame-state.md)。`FirstPersonModelState` 与真实 JNI owner 测试提供了局部证据，宿主放置与 shader 范围见[渲染问题](../../status/known-issues/rendering.md#重复消费与第一人称)。复用了 canonical 姿态，不代表本次 draw 的元数据一定仍然有效。 |
| AN-05 固定入口许可与领域动作 | 顶层准入建立有效借用并固定 `ACTION` 权限，内部维护 subject、receiver、值消费状态与函数调用深度。普通动作立即交给领域 owner 执行，而 coded controller 只能在 `process` 的选择窗口内、player 消费之前修改。本地 sync 在正常借用结束后恰好交付一次，并独立尽力上报原选择，同时忽略自身的回显。远端安装前的等待序列归 MN-16 管理；匹配安装但没有对应 handler 时直接终止并丢弃，消费时每个 sync 及其延后动作先排空，再采用下一段状态。遇到普通异常立即清除未交付载荷。如果删掉窗口限制，keyframe 或 defer 就会越权修改 controller；如果取消借用后再交付，就会同步重入源 owner。 | `D-EFFECT`、`D-ENTITY`；动作去重与 owner 边界属 **Essential**，具体窗口与专用 FIFO 属 **Derived**。 | **Fact**：`MolangContext`、`ControllerActionBuiltins`、`CodedAnimationController.process`、`EntityExpressionRuntime`，以及[运行契约](../../architecture/animation/molang-runtime.md#invocation-与效果)。owner 集成测试已覆盖真实的 process、player 与源失败交付轨迹，但不替代实机音频与网络验证。 |
| AN-06 模型覆盖、内建动作桥接与解析复用 | Hybrid 优先选用模型声明的 controller，未覆盖的行为回退到 coded 或默认实现。运行时 controller 各自维护来源和解析结果 map，多个 player 共用解析结果，子 controller 相互独立；资源重绑定或使用结束时清空缓存。如果删掉桥接，基础动作会丢失；如果删掉缓存，只会增加共享查询，不改变播放语义。缓存引入了来源失效责任，且成功引用与缺失键会随不同名称数量持续增长，目前没有容量上限。 | `D-CONTROLLER`、`D-VANILLA-ACTION`、`D-AN-FALLBACK`；桥接属 **Essential**，解析缓存属 **Derived**。 | **Fact**：`HybridAnimationController`、`ControllerAnimationCache` 及 controller 集合；详见[播放选择](../../architecture/animation/controllers-and-playback.md)、[资源裁决](../../architecture/model-management/client-resources/implementation/resource-ownership.md#动画解析与保留)与[默认回退](../../product-decisions/decisions/model-fallback.md)。真实 Coded 与 Bedrock 定向序列验证了预热后能减少共享解析且不建读批次，但 predicate 旁路仍会访问资源，吞吐与内存占用尚未实测。多种 controller 按同一语义建模，不按实现类数重复计数。 |
| AN-08 现存并行动画的旋转混合补丁 | Parallel controller 至今仍启用 `blendRotation` 与 cached point accumulation。直接删掉会改变并行动画的数值结果，但目前缺少受保护的作品样本来确认期望表现。 | 根理由缺口 `H-BLEND`；**Uncertain**。 | 机制存在以及源码注释“解决一个历史遗留问题而保留的动画混合”“旧版 blendRotation 只有高并行动画在用”均属 **Fact**（见 `AnimationProcessor`、`CodedAnimationController`）。由于原问题是否已经消失尚无定论，不能标为 `Historical`，兼容等级判断见 [Q-06](open-questions.md#q-06)。 |
| AN-09 生成依赖级兼容 checker | 编译期分析自有代码及外部依赖，生成 checker、probe 与 manifest。直接删掉生成端会导致当前 runtime 因找不到 checker 而跳过 handler。 | `A-AN-04`；**Derived**。 | **Fact**：`ExtensionCompatibilityProcessor.finishCompilation`、`CompatibilityAnalyzer.analyze`、`CheckerSourceGenerator`，以及[扩展注册](../../architecture/integration/implementation/extension-loading.md#扩展兼容检查与注册)。可选降级义务能解释为什么需要加载前门禁，但不足以独自证明整套生成管线的收益，详见 [Q-07](open-questions.md#q-07)。 |
| AN-10 先检查再加载及局部失败隔离 | Checker 通过前绝不初始化 handler。Molang collector 先校验安全资源、全量（all-of）依赖以及 auto 与 manual 资格，随后才执行解析、初始化和绑定，拒绝所有冲突类，完成后冻结 registry。链接、构造和注册失败按原 owner 局部隔离。内部 SW 手部适配采用精确 metadata 门禁、冷期构造与注册回滚以及 getter linkage 隔离，既不借用扩展 checker，也不包裹 YSM 与 consumer 输出。如果去掉加载前隔离，不兼容的可选代码会提前初始化，甚至向外传播类加载错误。 | `D-EXT`；**Essential**。具体的反射结果协议由 AN-09 派生，但局部隔离义务本身不依赖生成器。 | **Fact**：`CompatibilityQualification`、`MolangExtensions.Collector.freeze`、`ExtensionEventHandlerRegistration.prepare`、`ExtensionEventHandlerLoader.registerOne`、`SWarfareCompat.registerHandAdapter`、`ReplacePlayerArmRender.readHost`、`ExtensionEventHandlerRegistrationTest`、`SWarfareHandAdapterTest`，以及[可选联动决策](../../product-decisions/decisions/integration-risk.md)。 |
| AN-11 连续顶点与宿主 consumer 的双路径 | 遇到可识别连续布局的 consumer 走 direct 路径：预留方直接交付内存地址、字节容量和 backing anchor，JNI 原地消费该借用。其他未知布局的 consumer 则走 fallback 路径，先写入中间数组再回放。删掉 fallback 会丢掉未知布局的 consumer，删掉 direct 则会失去直写优化。 | `A-NATIVE`；**Derived**。`D-OUTPUT` 要求不同路径语义等价，但不强制采用当前的双路径结构。 | **Fact**：`NativeRenderer.probeVertexConsumer`、`NativeRenderer.render`、`FallbackVertexWriter`，以及[顶点输出](../../architecture/rendering/implementation/vertex-output.md)。受控输出成本入口见[帧路径基准](../../tools/benchmark/README.md#帧路径契约成本)，完整帧吞吐尚无结论；两条路径的视觉等价仍待[实机验收](../../status/known-issues/rendering.md#待验证场景)。 |
| AN-12 成功后提交宿主输出 | Direct 路径先预留（reserve），只有 native 成功返回后才推进（advance）写指针；fallback 路径同样只在成功后才回放顶点。同步返回的 boolean 仅在提交完成，或经 native 校验确认属于有效空结果时才返回成功。遇到外部容量不足、宿主矩阵问题或纯组合溢出拒绝时保留原姿态，只有 publication 损坏时才撤销资格并交由 producer 恢复。如果删掉这道门禁，native 失败前写入的部分顶点就会被提交到宿主场景。 | `D-HOST`、`A-NATIVE`；**Essential**。 | **Fact**：`NativeRenderer.render`、`VertexBufferAccessor`、真实 JNI 输出集成测试与 native 四模式失败分类；source 校验与汇合规则归[输出接口](../../architecture/rendering/implementation/vertex-output.md)。第一人称统一 renderer 复用同一 boolean，标准与 SW adapter 只在有效消费后取消该侧渲染，背景从不取消宿主；hook 拒绝与缺根不算合法空结果。实体求值失败不交付 Prepared，输出也不使用 consumer 阶段标记或异常中继。成功门禁不是 consumer 事务，回放异常按[产品失败边界](../../product-decisions/decisions/failure-isolation.md#bcrender-failure-does-not-corrupt-scene)原样交还宿主，不伪装为正常 boolean。 |
