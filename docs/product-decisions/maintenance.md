# 产品决策维护规则

按独立判断分层，不按整段裁决归档。本树保留产品承诺、产品理由及必要边界；机制与工程理由进入架构，格式与协议细节进入标准，当前支持和验证结论进入状态文档。自包含要求读者能完整判断产品义务，不要求保留全部技术推导。

可观察不等于已承诺。替换机制仍满足承诺的结果、领域语义和外部契约时，不应修改产品决策；产品确实约束机制时，保留该约束，实现方式仍下沉。纯分层与归约须保持产品含义；改变既有承诺或下游与本树冲突时，由维护者提交产品负责人裁决，不能以当前实现或“技术细节”为由自行改写。

仅为独立产品选择新增 DD；补充契约或例外归入已有 DD，同一选择的重复 DD 合并。合并须保留独立契约、理由、优先级、例外与互斥条件，主题相近不足以合并。机制连同工程理由下沉；冗余节点的独有含义被承接后才删除。保留存续判断的 ID，不为保留 ID 维持重复定义。

每次修改完成以下影响闭环：

1. 修改前收集涉及的旧/新 ID 和包路径；包头、公共规则或例外变化须包含受其限定的全部节点。用 `rg` 精确检索本树及下游的 ID、包路径与名称。
2. 读取命中的完整裁决边界，检查嵌套 BC、显式 Decision 归属、Constraints、条件 Needs、Requirement 与 Select/Uses。区分导航变化与含义变化，沿受影响依赖继续检查，直到没有未处理的适用依赖；正文未变不代表不受影响。
3. 更新唯一正文、下游引用及 Landing/反向索引，结合最终 diff 复核范围，再搜索退役 ID 和旧路径。检索只给出候选，未记录的依赖仍须按语义判断；不另建长期影响台账。

已裁决下沉的规则及其例外应在架构或标准中有明确落点。移走机制后，仍有产品含义的节点保留 ID；不再有产品含义的节点退出本树。下游改为引用规则的新落点，复杂度地图同步复核根依据；不保留空节点维持旧路由。

从仓库根目录运行：

```sh
python docs/tools/check_docs.py
git diff --check
```

修改 Mermaid 时另做渲染校验。检查 ID 唯一、引用有效、BC 归属、因果关系无环、需求状态与缺口一致、Landing 与反向索引对应；条件 Needs 和导航允许成环。

结构校验不能证明分层、归约或影响范围完整。语义复核须确认承诺有产品依据，理由与例外自包含，归约未丢失义务，机制未提升为承诺，当前实现/未来方向/验证状态未混淆。本页维护规则应随文档约定同步更新；规则属于文档治理，不创建 DD/BC。决策闭合不表示生产实现或运行时验收通过。
