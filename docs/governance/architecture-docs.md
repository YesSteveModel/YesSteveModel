# 架构文档维护

按[文档政策](documentation-policy.md)确定信息取舍和唯一权威。产品含义变化或冲突按[产品维护规则](../product-decisions/maintenance.md)裁决；文档整理不改变生产契约。

## 组织与递归展开

`architecture/README.md` 是唯一系统入口，拥有系统核心模型及按问题导航。实际子系统以 `overview.md` 承载核心设计；设计专题与入口同级，实现映射按需进入 `implementation/`。不设子系统 `design/`、同级 `README.md` 或实现总览，也不要求设计与实现页对称。

本级应能独立解释输入、结果、责任、发布条件、失败后果与结束义务。下级可细化节点、交接或生命周期；折叠下级后，本级契约仍成立。父级拥有组合规则，下级拥有局部接口，父级不复制全部接口、状态和例外。跨分支规则归实际组合责任方，不按最近公共目录机械上移。

所有子系统均可递归分解，不限制深度。拆分应具有独立职责与结果、状态或资源责任、交接与失败边界，以及局部阅读价值。线程、package、类、篇幅或目录对称不能单独证明边界。只有重复摘要或符号列表时合并；交接专题不自动成为子系统。

## 设计入口结构

任意层级的子系统 `overview.md` 使用以下六个二级章节。专题不重复套模板；无长期实例时说明操作由哪个调用作用域承载。

| 章节 | 本级应解释的内容 |
|---|---|
| 职责与边界 | 输入、结果、权威事实与相邻职责 |
| 运行作用域与所有权 | 上级生命周期、写入者、保留者与关闭责任 |
| 数据流与交接 | 交付物、接纳条件、责任转移、拒收 |
| 生命周期与失败 | 建立、替换、撤销、迟到结果与真实终态 |
| 关键契约与设计取舍 | 不变量、非显然理由、代价、限制和例外 |
| 实现与验证入口 | 必要责任映射、status 差异与验证入口 |

下级入口应链接直接上级拥有的契约章节，并说明所细化的职责。上级目录不自动拥有全部 backing；目录是职责树，交互仍可形成图。

## 关系用词与图形

| 用词 | 固定含义 |
|---|---|
| 上级生命周期 | 决定接纳或存续的作用域，不自动拥有 backing 关闭权 |
| 状态写入者 | 修改并发布某份可变事实的主体 |
| 保留者 | 通过强引用、lease 或 pin 保活资源的主体 |
| 关闭责任方 | 执行最终关闭或发起规定清理动作的主体 |
| 借用者 | 只在指定窗口访问资源的主体 |
| 共享范围 | 允许复用同一资源的消费者范围，不等于共享可变状态 |

探索非线性关系优先用拓扑图，比较 owner 职责或事件影响优先用表格；文字补充条件和例外。每张图说明抽象范围与边的含义；请求、数据、持有和必需顺序使用标签或线型区分。颜色不单独表达语义，不把并行关系画成虚假的统一状态机。简单线性事实可直接陈述。

应区分取消请求与真实终态、发布资格与合法旧使用、lease 关闭与物理回收、对象寿命与单次使用、服务结束与进程结束。只记录必要偏序。Ownership 转移应说明成功条件和失败后责任；多个保留者不等于多个关闭裁决者。

## 契约引用与变更传播

重要交接、发布资格、资源终态及多域依赖规则使用可精确引用的 Markdown 章节。页内标题唯一，语义不变时保持标题稳定；不增加逐段 ID 或双向台账。

引用方说明依赖关系及前提：下级细化什么，实现落实什么，消费者依赖什么。一次章节引用可覆盖同一组前提，普通导航不等于依赖声明。边界变更先更新权威正文，再沿入链复核下级、实现、消费者和上级组合；上一层不受影响时停止传播。

纯内部变化只在影响已保留的架构事实时修改文档。入链可临时生成反向列表，但不能证明覆盖全部消费者。路径和标题变化应修复引用含义，不只替换同名文件。

## 实现信息准入

每个独立信息块应同时通过以下三道门槛。页面开头有设计链接不代表整页细节都应保留。

| 门槛 | 判断 |
|---|---|
| 架构关联 | 落实哪个具体契约、职责边界或承重选择？ |
| 独立增量 | 补充哪个设计未定义的必要写入者、门禁、转移点或共享身份？ |
| 最低精度 | 删除具体结构、步骤或数值，是否会丢失该责任关系？ |

保留信息应能解释省略后会导致哪项架构误判。代码难以还原、局部算法需要正确、调试便利或已有正文，均不能单独证明价值。含有 owner、状态、生命周期等词也不自动准入。可替换的责任映射仍可保留，不以可替换性单独判删。

### 默认删除与例外

| 默认删除 | 通过三道门槛后可保留的最小信息 |
|---|---|
| 私有布局、字段表、文件名及路径配方 | 身份隔离、兼容、验证与原子提交关系 |
| helper 顺序、循环、全调用链 | 必要偏序、交接门禁和拒收责任 |
| SIMD、scratch、缓存重建和调度算法 | 输出等价、容量和调用方并发边界 |
| 调优常量、压缩等级、优化目标数量 | 跨边界协作或预算裁决确实依赖的精确值 |
| 全量成员、状态及资源表 | 关键所有权和发布关系所需的少量对象 |
| 测试清单、测量快照、迭代过程 | 指向验证、状态和当前设计理由的链接 |

数值可观察、来自代码常量或从产品下沉，都不自动获得保留资格。既有产品和标准约束按原权威规则处理。

递归拆分不改变信息资格。跨类、目录、线程或 Java/native 不自动构成架构边界；合并目录后，真实裁决、所有权和调用方义务仍应成立。不能把算法阶段拆成子系统以保存局部知识。

删除内容不自动转存复杂度地图、附录或 reference。局部维护知识是否需要注释或测试，应另行判断。

### 页面保留与定位

实现页与整个 `implementation/` 均可不存在。只剩设计复述时删除；只剩少量责任符号时放入设计的“实现与验证入口”；独立解释必要映射时才保留专题。相同规则只保留一处权威正文，不设篇幅或数量指标。

实现页开头链接精确设计章节并说明落实关系。少量稳定符号可定位责任，不附源码路径、行号、成员清单或无约束价值的调用步骤。

## 流程与横向导航

`views/` 用于跨职责树的关系投影或多场景比较；`flows/` 用于单个跨域场景的展开。两者均可选，不套用子系统六章模板，不建立自己的 overview，也不为同一问题重复建页。已有设计正文能独立解释关系时直接链接正文。

视图应有明确阅读问题，例如“哪些 owner 同时保留同一资源”或“disconnect 分别结束哪些工作”。允许为连通拓扑和比较事件而重复必要摘要，每组关系应精确链接其权威章节。唯一权威约束规则的定义位置，不禁止横向摘要；只有一组跳转链接不能代替跨域关系说明。

图表达共享关系与必要偏序，分别标明边的含义；表格按 owner 或事件比较归属、保留、关闭责任与结束条件。配额摘要注明适用范围、计价对象及归还条件，不把局部预算相加为总内存上限。不要建立全量资源、成员、线程或参数台账。视图不能新增契约、保存已裁剪细节，也不能代替实现页所依赖的设计正文。发现独有规则时，先归入实际责任方的正文，再保留投影。

系统入口同时提供按问题导航与横向视图入口。规则变化沿入链复核受影响的图和摘要；检查器只验证结构与依据链接，不证明摘要完整或与规则一致。验收时，只读视图应能解释其声明范围内的关系，精确条件和例外可沿链接进入正文。是否删除视图取决于阅读价值，不以没有独有规则作为删除理由。

## 修改与验证

1. 定位产品依据、权威设计和必要当前映射。
2. 按独立事实筛选，核对条件、例外、身份和终态。
3. 承接应保留事实，复核取舍后修复有效入链。
4. 更新产品 Landing、反向索引及复杂度依据。
5. 核验本域保真后删除旧正文和临时迁移表。
6. 执行结构、引用、图形及跨域语义检查。

未闭合冲突不能因链接有效而判定完成。发现依据缺口时定向核验，不从实现补造产品承诺或性能收益。未落地差异归 status，未选择方向归 future。

从仓库根运行 `python docs/tools/check_docs.py`、`python docs/tools/test_check_docs.py` 与 `git diff --check`。修改 Mermaid 时另做渲染校验。检查器验证递归结构、章节、依据链接、锚点唯一、可达性和复杂度关系，不判断承重价值或消费者完整性。

语义复核覆盖启动、连接替换、reload、迟到安装、暂停/reset/retire、独立音频、lease 与物理回收、发布及宿主消费失败、转换与导出。每项定位裁决者、写入者、保留/关闭方、门禁与终态。只读父级应能解释边界行为，折叠下级不得改变契约。结构与文档校验不证明生产行为或性能。
