# GUI Molang 解释语义

本页定义普通 GUI 路径下 Molang 表达式的独立准备、动态值与动态调用规则；AOT 与解释两条路径如何选定由[Molang 运行](molang-runtime.md#执行用途与主体资格)决定。Java 扩展的作者边界仍归[共同声明](molang-declarations.md)，AOT 静态规则仍归[静态语言](molang-static-language.md)。两条路径共用同一套 `MolangContext`、冻结声明、源执行帧和宿主效果出口。

## 独立准备与来源

与 AOT 对整套动画集做全量静态分析不同，GUI 路径按需准备当前真正消费的表达式：宿主按动画集固定来源命名空间、接收模型的语义选项以及用户函数获取能力，Semaweave 只接收当前需要消费的 Portable Program 字节。准备阶段会校验该输入的全部结构并绑定符号（包括未执行分支），但动态值类型留到实际操作时再检查。因此准备开销不包含无关表达式、未调用的函数体或整套 GUI 编译闭包。

同一个动画集代共用一个解释环境，普通变量与 Roaming 的规范名称各自登记为只追加的稳定整数槽位，局部变量名和参数槽位则归属于单个程序。并发准备时只同步名称登记，各程序的编译工作区与动态类型判断完全独立；如果准备中途失败，已经登记的无值名称允许保留在目录中。

准备产物是一棵不可变的绑定求值树，其中固定了操作种类、变量槽位、访问方式、Java 调用形状、权限、调用归属和候选方法集合。用户函数调用在准备期只绑定名称与精确来源身份，函数体推迟到实际调用时才读取准备；相同文本的本地函数与默认补全函数保持独立身份。仅凭当前已加载的程序子集只能说明信息尚不完整，不能据此断言某个函数不存在、变量类型永久固定或字段集合完整。

当权威来源已经确认某个用户函数不存在或参数个数不符时，调用直接返回 `missing`，不求实参也不进入函数深度计数。其余用户函数调用按以下步骤执行：

1. 检查源帧的活跃函数深度；到达第 33 层时，在获取函数体和求参之前即终止当前顶层表达式。
2. 按已固定的来源身份取得并独立准备函数体；递归调用只引用身份，不展开函数闭包。
3. 若确认缺名或参数数量不符，返回 `missing`；若函数存在但无法取得、内容损坏或绑定失败，则结束当前 GUI 实例。
4. 从左到右求值实参，建立本次调用的私有局部变量并执行函数体。函数体继承当前查询环境、源变量与源权限。

只有完整且有效的本地及适用默认来源范围，才能证明某个函数确实不存在并写入负缓存；局部已加载的子集不具备这一证明力。未被消费的损坏函数体不会妨碍其他表达式准备；一旦实际消费到损坏函数，异常直接展开到顶层入口，诊断只保留源顶层身份与原 `Throwable`。

[来源版本除零选项](molang-static-language.md#来源版本与除法)与非有限值策略在解释环境内固定，默认补全与公共函数继续沿用接收模型的选项。数值投影、逻辑短路、[运算符分组](molang-static-language.md#运算符分组)、[独立循环次数及函数深度](molang-static-language.md#循环与函数深度)、[引用与箭头](molang-static-language.md#引用与箭头)以及词法控制流均继承公共语言契约，仅动态行为差异由本页单独规定。

## 数值消费

解释路径沿用宿主的[算术数值策略](molang-static-language.md#来源版本与除法)。闭集数学函数允许接收非有限中间值，并将自身的定义域外或溢出结果归一为 `+0`。输入准入阶段检查字面量和外部动态值。声明承诺返回有限值的 Java 方法由调用方直接信任，可空 Java 返回按共同声明规则归一。

| 消费边界 | 有限性检查与失败后果 |
|---|---|
| 条件、逻辑、比较、循环次数、索引及整型转换 | 使用数值前检查，防止非法中间值转为有效条件或索引 |
| 变量、字段、Roaming 写入，以及用户函数参数与返回 | 交付前检查，失败时不发布本次写入也不进入函数体 |
| 获准的 Java 实参 | 从左到右逐参检查，失败时后续实参和声明方法均不执行 |
| 顶层有值结果 | 交付前检查，失败结束本实例；单纯丢弃的数值结果不额外检查 |

在检查延后到消费边界之前已经执行的获准效果仍保留，不回滚；普通动态类型失配也在实际消费点触发失败。

## 动态变量与缺值

普通变量和局部变量按稳定整数槽位访问实例或当前激活帧的私有动态值数组，同时保存实际值与缺值状态。赋值、传参、返回和 `??` 都原样保留 `missing`；未赋值的普通变量和不存在的字段读出 `missing`。在本次激活中尚未初始化的 `t.*` 读出未指定值，可能观察到本实例复用缓冲中的残留值（参数初始化、已写局部值、递归调用隔离和实例间隔离均保持不变）。只有在真正作为标量消费时，才按[公共数值投影](molang-static-language.md#对象-presence)供应 `+0` 或 `false`，这一消费不会把默认值写回变量槽。

普通赋值直接记录右侧的实际类型：`v.a = 0` 保存数值，`v.a = false` 保存布尔值，`v.a = null` 撤销旧值并记录缺值。Java 返回的缺值带有声明类型，普通 `null` 则是无类型缺值。`String`、只读数组和精确引用维持[共同声明](molang-declarations.md#值与-presence)规定的值域与访问能力。

各程序在首次实际进入时，按自身需要扩容实例存储并保留已有值；只有实际调用到的用户函数才会引入新名称，父级求值继续访问同一份底层存储。外部按名称只读查询时，未知名称直接返回 `missing`，不会在环境中登记新槽位。

`Roaming` 依然是初值为 `+0` 的必有值 F32，安装时通过所属环境的 `newRoamingState(role)` 创建状态对象。环境只共享名称到槽位的目录，具体数值、已声明成员集合和 dirty 标记都归属于实体实例；只有本实例实际进入的程序或同步输入才会登记成员，其他实例用过的名称不会混入本实例的导出结果。

外部的 full 或 patch 更新可以先于程序准备引入名称，由于共用同一目录，后续程序读写仍会命中同一份值；full 会清零本实例已知字段，patch 只覆盖携带字段并保留其余值。宿主在网络边界按名称转换外部编号，环境槽位不替代传输身份。同步角色与写入窗口保持不变，独立准备不要求完整的程序清点（inventory）或 AOT 布局。

## 平面结构体与字段写

脚本结构体在解释路径中用不可变的平面 `Map` 值表示，字段值允许为 F32、BOOL、`String` 或 `missing`。字段可以动态新增或改变类型；赋值、传参和返回可直接共享旧快照，后续字段写入再构造并发布独立的新快照。Java record、只读数组及其元素维持不可变。本页不引入嵌套结构体、可写数组或引用类型字段。

字段写入按固定三步执行：先捕获可写变量的槽位和当前接收值，再求值右侧表达式，最后发布新结构体：

- 当接收值为缺值、F32 或 BOOL 时，新建一个只包含本次写入字段的结构体。
- 当接收值已是脚本结构体时，保留其余字段并更新目标字段；当 Java 平面 record 存入普通可写变量后被写字段时，生成一份独立的脚本结构体。
- `String`、数组和引用不会因为字段写入自动转成结构体；非法字段值或右侧求值失败时，不发布更新，但右侧已经产生的其他效果保留。

即使右侧表达式重新赋值了该变量，或者懒加载函数触发了存储扩容，也不会改变第一步已经捕获的接收值；最终结果按逻辑槽位写回当前数组，右侧过程中建立的别名仍看到旧快照。对临时 Java record 执行字段写时，沿公共规则依次完成接收者求值、右侧求值和必要检查，仅省去最终写回。对缺值或标量读取不存在的普通字段返回 `missing`，但访问未声明的 Java 成员或非法引用仍触发失败。脚本无法枚举字段名，因此给字段写入缺值与删除字段等价。

## 比较

F32 与 BOOL 的混合比较、对象与标量的投影比较、同类 `String` 或数组的内容比较，以及引用身份比较，均遵循[公共规则](molang-static-language.md#对象-presence)。解释路径中不同类型的对象比较一律判定为不相等（`!=` 取反），且不调用作者实现的 `equals`。

脚本结构体在忽略缺值字段后，比较字段名集合与各字段值，与字段顺序无关。Java record 保留自身声明类型；如果它经字段写变成了脚本结构体，之后便按脚本结构体规则比较。缺值与缺值相等；缺值与非缺值的 F32、BOOL 或 `String` 比较时，分别按 `+0`、`false` 或空串消费；缺值与非缺值的结构体、数组或引用则一律不相等。比较过程不改变 `??` 所观察的缺值事实。

## 冻结 Java 调用

对已解析的 Java 外部函数，无括号访问与空括号调用都视为零参调用，共用参数个数、默认值、权限门禁与失败规则。解释路径只在准备期冻结的候选方法集合内筛选：先检查固定 ACTION 权限、选定归属的 subject 资格以及参数个数，通过后再从左到右逐个求值实参（每个实参只求值一次）。一旦某个实参使所有剩余候选全部失配，立即抛出运行时类型错误，后续实参和声明方法均不再执行。

候选筛选依据当前实参的实际值类型，精确匹配优先于公共标量转换。普通 `null` 对所有可接纳候选拥有相同的转换等级，带有声明类型的缺值则按其声明类型匹配。全部实参通过后，按[逐参数支配及规范 JVM 成员排序](molang-declarations.md#作者签名)选定唯一目标方法；声明发现顺序、预期返回类型和参数数值均不参与重载决策。

默认值只补给脚本中省略的参数位置，显式传入 `null` 仍计入 `argc`；类型化变长数组构造与 Java 返回值归一遵循共同声明。调用借助所属声明与加载环境的类型化调用计划及缓存的 `MethodHandle` 执行：单候选直接按固定签名消费，存在多个候选时才逐参筛选。调用时传入本实例的接收者和上下文，可空返回按声明归一。调用计划按符号、访问形式和实参数量在同一环境内复用，只保存签名和不可变链接；求值节点直接计算实参，计划本身不持有表达式、实参、实体或上下文，随 store 的解释环境退休而释放。

箭头表达式只切换查询环境，ROOT 始终从源帧取得匹配的上下文与 binding，源变量、用户函数、ACTION 权限、函数深度、`defer` 和效果归属都不会迁入目标。解释绑定与 AOT 绑定各自独立建立，实际 `Class` 或加载环境不同的同名声明互不通用。

## 实例、驻留与失败

`AnimationStore` 共享不可变的绑定程序，解释环境目录只保存名称与槽位编号，调用计划只保存声明与适配链接。每个 GUI 实例独占变量值、局部激活、controller、组件及上下文，所有操作沿[实体执行权](entity-lifecycle.md#执行权与任务交接)串行且不可重入。一轮求值复用同一个 `MolangContext` 和 frame，引擎复用实例私有的根状态，同步退出时立即解除临时借用、返回值和正常控制流转移；普通变量、Roaming、主体样本及本轮动画与 controller 选择维持原归属。根局部缓冲按程序需求复用，不逐条表达式清空，其中的引用可能存活到槽位被覆盖或实例关闭；递归函数各自拥有独立的局部帧，箭头表达式则共享所属激活帧。实例退出即清除全部私有状态；同 store 下的新实例重新初始化私有值并复用共享程序。

已经访问过的程序随 store 驻留，其使用保护、取消与关闭由[动画资源所有权与退休](../model-management/client-resources/overview.md#动画资源所有权与退休)统一定义。

在 `cache-only` 模式下，解释路径可以从本地已有的未绑定输入解码并在内存中绑定；若取得阶段输入不足则返回未命中。实际求值过程中若发生输入读取失败，会直接结束当前实例，不回退已经发生的效果，也不会触发网络拉取。用途与权限边界见[用途与派生物](../model-management/client-resources/overview.md#用途与派生物)。

各类异常与中止的处理边界如下：

- **正常值返回**：合法缺值、完整来源证实的缺名、参数数量不符和权限门禁拒绝均按正常值语义返回。
- **拒绝准备**：结构损坏或链接失败直接拒绝该程序准备。
- **结束当前实例**：运行时类型错误、声明方法抛出的真实异常以及已消费输入读取失败都会结束当前 GUI 实例，已有写入和领域动作不回滚。运行时类型错误不会像 AOT 那样触发整程序替换。
- **仅截断当前表达式**：用户函数深度超限只终止当前顶层表达式，必要窗口退出后仍可继续执行下一条表达式。
- **异常展开与报告**：内部函数、箭头和 Java 调用直接向上传播原异常，宿主在顶层入口统一报告一次（仅保留源顶层身份与原 `Throwable`）并分类处理，不维护被调函数或节点轨迹，也不做失败暂存；普通失败实例直接废弃，不尝试恢复复用。共享程序与其他实例不受影响。严重错误、清理失败与 required default 的处理遵循[Molang 故障分类](molang-runtime.md#求值失败)。

解释路径只限制活跃用户函数深度，不限制语法树深度或箭头嵌套深度，也不承诺任意深输入的 Java 栈安全。取消检查分布在持续工作边界：准备阶段在入口、解码与绑定交接以及函数输入读取点观察取消；执行阶段在入口、循环回边、函数读取前后和顶层交回时观察取消。直线执行段可以跑到下一个观察点，已经获准的效果不回滚；取消后不再发布结果，借用资源与退休完成仍须等待实际工作退出。

独立准备去掉了整套动画集的分析开销，但也有明确代价：名称目录随解释环境长期保留，较高的槽位编号可能带来实例数组空洞，此外名称登记、数组扩容、根局部引用保留、动态分派、结构体复制以及首次读取函数体都有运行成本。验证方法见[Molang 集成验证](../../verification/molang-declarations.md)，当前覆盖与性能缺口见[动画问题](../../status/known-issues/animation.md)；独立准备机制本身不证明首帧或帧率收益。
