# Molang 静态语言规则

本页定义 AOT 编译路径下的静态定型、调用恢复、presence 传播与对象写入语义。普通 GUI 的动态执行差异由[解释语义](molang-interpreter.md)定义，Java 扩展的作者边界由[共同声明](molang-declarations.md)定义。解释路径只继承本页中被显式引用的公共投影、控制流与数值规则，不继承整集静态定型和整程序替换。本页规则由编译策略（compilation policy）显式启用，不改变模型线缆格式或其他宿主的默认语义。

## 对象 presence

语言中的对象包括 `String`、平面 record（含 vector）、只读数组以及精确类型的 `Entity` 引用。空串、空数组和全零 record 都属于“有值”（present）对象；空串仍保留 `String` 类型、内容判等以及传入 Java `String` 参数的资格。

当上下文已确定需要 F32 或 BOOL 目标值时，合法来源按以下规则消费。转换路径在编译期按来源类型确定，运行时只检查固定载体的值；来源表达式只求值一次，且投影不会改写来源自身的类型、内容或缺值状态。

| 合法来源 | F32 消费 | BOOL 消费 |
|---|---|---|
| 有限 F32 `x` | 保留原 bit 位，含 ±0 | `x != 0` |
| BOOL `false` / `true` | `+0` / `1` | 原值 |
| 普通 `unset`、脚本 `null`、类型化 missing | `+0` | `false` |
| 空 `String`、零长度只读数组 | `+0` | `false` |
| 非空 `String`、非空只读数组、其他非缺值对象 | `1` | `true` |

`String` 投影不会解析数字：`"0"`、`"false"` 和空白串都转为 `1` 或 `true`。数组只检查长度，不递归检查元素；全零 record 和零向量均转为 `1` 或 `true`。这套转换规则覆盖算术、大小比较、逻辑运算、条件分支、循环次数、数组索引、入口返回值、用户函数参数消费以及 Java 标量参数。

各类相等比较（`==` 与 `!=`）规则如下：

- **F32 与 BOOL 混合比较**：统一按数值比较。
- **对象与标量比较**：先按上表将对象投影为 F32，标量侧保留原值，与左右顺序、是否字面量无关。例如 `2 == true` 为 `false`，非空对象与 `1` 相等、与 `2` 不等。
- **同类型对象比较**：`String`、record 和数组按字段或元素内容比较，`Entity` 引用按 `==` 比较对象身份（两个 `null` 相等），均不调用作者实现的 `equals` 或 `toString`。不同对象 schema 即使都能投影为标量，也不允许直接比较。
- **含缺值的同类型比较**：已完成定型的 F32、BOOL 与 `String` 同类型比较中，missing 分别按 `0`、`false` 与空串参与比较，missing 与 missing 相等；比较过程不会把默认值写回变量槽。

`??` 运算符只检测缺值：`0`、`false`、空串和空数组都属于有值，因此直接保留左侧而不求值右侧。被缺值观察覆盖的变量读取与内部复制会保留 presence 状态，直到真正发生标量消费时才产出有值的 `+0` 或 `false`。

缺值观察需求从 `??` 的左侧出发，沿着槽复制、赋值结果、分支以及用户函数参数与返回值反向传播。被观察需求覆盖的变量会区分“已初始化”与“未初始化”；其余变量不记录初始化状态，在写入前读取或写入缺值时直接归一为 `+0`、`false`、`null`、空串或空数组。`Roaming` 固定为必有值的 F32（初值 `+0`），直接读取及已证明来自它的传播路径不会求值 `??` 右侧。`VALUE` 出口、冻结的 transient 边界与 record 字段保留各自的观察契约。临时 watch 沿用模型已冻结的表示，不能反向开启模型原本未保留的初始化状态。静态分析覆盖所有有效写入，不针对具体控制流路径证明某个变量必然已被初始化。

向已定型的对象目标写入原始 F32 零字面量或 BOOL `false` 字面量时，会触发同 schema 清空（如果该槽未保留 presence，则归一为对应默认值；赋值表达式的结果与实际写入值一致）。这条清空规则不授权不同对象类型之间互转；同类型对象赋值、字段访问和索引继续遵守原有隔离与访问规则。

## Literal 边界与定型

前端将 `null` 直接编码为 `unset` 字面量，不查找宿主符号。

字面量资格取自前端输出的原始规范节点，在常量折叠和类型转换之前判定。括号本身不产生节点，因此 `(0)` 仍是字面量；但 `+0`、`-0`、`1-1`、函数调用、变量、赋值、条件和顺序表达式都不是字面量，即使它们的求值结果恰好是 `0`、`1` 或 `false`。F32 的 `+0` 与 `-0` 载荷在判等时都视为零；非有限字面量属于非法输入。编译器不会通过试跑 provider 或插入运行时数值守卫来放宽字面量接纳。

F32 零字面量写入未定型位置时只构成弱类型依据：如果同一约束流中存在对象类型依据，该零字面量就解释为对应对象的缺值；如果最终只有弱零依据且允许默认类型，则定型为有值 `0` 的 F32，`??` 不会走向右侧。与之相对，BOOL `false` 字面量会直接将未定型位置定型为 BOOL，只有当目标已由其他依据确定为对象时，它才表示清空对象。通过表达式算出的零（非字面量）则始终提供普通的 F32 类型依据。

未声明类型的持久槽、局部槽位、分支结果以及同一用户函数版本的返回值，只允许 F32 与 BOOL 异型合流为 F32：合流后 BOOL 路径产出 `0` 或 `1`，F32 路径保留原数值；纯 BOOL 流仍维持 BOOL。缺值本身不是类型候选，合流也不会提前把缺值转为默认值。对象与标量之间、以及不同对象 schema 之间一律构成类型冲突，不按标量可转换性自动归约。

在完整 target 范围内，编译器会跨所有入口以及 subject 与权限计划统一持久槽位的类型。用户函数按调用点独立推导：不同的静态实参类型、供参形状和消费需求可以派生有限个特化版本，但一个调用点的弱零字面量不能向另一个调用点借用对象依据。同一版本内的参数、返回值和局部槽位类型固定，不按运行时数值、presence、实体身份、调用 scope 或箭头嵌套深度生成版本。对象来源经赋值、转发和返回向外传播，下游的标量投影不会反向改变上游来源的类型；缺值同样贯通内部函数，直到最终标量消费点才转为 `0` 或 `false`。

递归函数组在入口处固定各成员的签名，所有回边在允许的静态转换后必须与入口签名匹配；多态递归属于编译期静态错误，不会拖到运行时耗尽深度或资源。局部恢复完成后，编译器从有效语法树重新构建函数版本、持久槽布局与 effect 信息，失效版本不会导出给临时编译使用。

## 运算符分组

运算符优先级从高到低依次为：调用、成员与索引，箭头 `->`，前缀 `!`、`-`、`+`，乘除，加减，大小比较，相等比较，`&&`，`||`，条件 `?:`，空值合并 `??`，赋值 `=`，`return`。二元运算符左结合；条件运算符右结合，真假两个分支都从条件层解析。括号和语句块可覆盖默认分组，`return` 读取所属语法边界内的完整表达式。

几个典型分组示例：

- `ref->q.x + q.y` 等价于 `(ref->q.x) + q.y`；`ref->q.x ?? 7` 可以观察解引用产生的 missing。
- `a->b->q.x` 等价于 `(a->b)->q.x`，第二次解引用仍从外层 parent 进入；如果写在块内嵌套，则消费当前的 child。
- `1 ? null : 2 ?? 7` 等价于 `(1 ? null : 2) ?? 7`。
- 无括号的连续赋值 `v.a = v.b = 3` 因左结合会触发非法左值错误，必须写成 `v.a = (v.b = 3)`。条件分支中出现低优先级的赋值或 `??` 也需要用括号或块包裹。

## 引用与箭头

`Entity` 引用保持精确对象身份，`null` 表示 missing。引用可以经由 `v.*`、`t.*`、条件表达式、用户函数参数与返回值、只读 `Entity` 列表、`VALUE` 以及冻结的 transient 传递，但不支持字段访问、方法调用、反射、codec、Roaming、网络同步或持久化。非 `null` 引用作标量消费时得 `1` 或 `true`，`null` 得 `0` 或 `false`；上述零与 `false` 字面量清空规则同样适用。

箭头表达式 `lhs -> rhs` 先在 parent 环境中按顺序求值左侧（LHS）一次，且 LHS 只接受 `Entity` 引用或 `unset`。如果结果为 `null`、目标实体已移除或不在源世界，则跳过右侧（RHS），按 body 类型返回对应 missing（`VOID` 则为 no-op）。目标合法时，在入口处捕获目标实体最近完成的样本输入，不要求目标装有模型，也不获取目标的执行权。目标实体被移除后，源变量槽里保存的引用不会自动清空：直接对引用使用 `??` 只检测引用是否为 `null`，对解引用结果使用 `??` 才会因目标失效触发回退。

RHS 中可以包含语句块、赋值、循环和用户函数调用。`return`、`break` 与 `continue` 沿原有词法边界传播，箭头本身不引入新的函数或循环边界。函数定义、变量槽、ACTION 许可、函数深度、动作与诊断归属全部留在源实体。可空派生（nullable derive）产生的跳过边必须保留未写入状态和正常出口，不能因静态判定 LHS 非 `null` 而删除。源槽位被覆盖或源实例结束时撤销该引用根；目标实体关闭不等待源槽清空。

## 循环与函数深度

`LOOP` 每次进入时对 F32 次数表达式求值一次，迭代次数取 `min(Math.round(count), 1024)`，非正数执行零次。顺序排列或嵌套的循环各自独立计数，某层循环被截断后仍继续执行后续语句。`FOR_EACH` 按已接纳列表的顺序遍历全部元素，支持 `break` 和 `return`。语言层面不设置跨语句的累计循环、值计算或临时区额度。

活跃用户函数深度上限默认为 32，进入第 33 层时在求参前即被拒绝；只有成功进入的函数才在 `finally` 中递减深度。箭头表达式和代码生成器拆出的物理 helper 共用源执行帧，不会重置深度计数。深度超限只截断当前顶层表达式，真实的 provider 异常或清理失败仍按原 owner 规则隔离。

## 来源版本与除法

算术运算产生 `NaN` 时，将该次运算的结果静默归一为有值的 `+0`，供后续表达式继续使用。正负无穷仍在有限值消费边界触发执行失败。AOT、GUI 解释和临时表达式采用同一数值策略。

当接收模型的 `origin_ver` 主版本号（major）小于 3 时，脚本中除以 `+0` 或 `-0` 会回退为有值的 `+0`；主版本号大于等于 3、版本号缺失或文本非法时关闭此回退。合法版本号由点分隔的十进制数字组成，可附带非空的 `-qualifier` 和 `+build` 后缀（后缀仅允许字母、数字、点、下划线和连字符）。解析采用全文匹配且不修剪空白；前导零不改变主版本号，超长数字也不会因整数溢出误判为旧版本。

AOT 的 main 与 arm、GUI 解释路径、默认补全以及公共函数均沿用接收模型的除零选项；独立的默认模型使用自身声明的来源版本；临时表达式继承编译时所借安装的冻结选项。

无论是否开启除零回退，两个操作数仍按从左到右的顺序各求值并做标量消费一次，回退不会吞掉实参求值失败；除数非零时继续遵循原有的符号零、下溢和溢出消费规则。取模运算符 `%`、数学函数以及 Java provider 内部的除法不受该选项影响。来源版本如何从历史模型保留，见[转换与导出](../asset-pipeline/implementation/conversion-and-export.md#历史输入的单向投影)。

## 调用解析与局部恢复

AOT 编译先对完整输入校验语法、编码和实际表示，不按节点数、嵌套深度或人工额度拒绝。随后按源码顺序解析符号和访问形式：

- **符号与参数恢复**：真正不存在的符号直接恢复为普通 `UNSET`，但把已知种类用错形式（例如把变量当函数调用）仍属独立错误。Callable 参数个数不符时直接恢复为 `UNSET`；数量相符时从左到右逐个分析实参，遇到首个具有独立类型依据的边界不匹配即让整个调用恢复为 `UNSET`，并停止分析后续实参。此前已经发现的独立字段、访问或存储错误不会被吞并成参数不匹配。
- **外部函数的无括号访问**：一旦符号解析为外部 Java 函数，裸读取 `f` 与空括号 `f()` 均视作零实参调用，共用重载选择、默认值、`argc` 与变长尾、effect、权限门禁与失败来源，且不缓存结果。如果最低参数数大于 0，两种写法都触发局部 arity 恢复，provider 不执行。函数返回 record 或数组后可继续按常规访问字段或索引，但函数本身不可作为赋值左值。真实变量、context 属性、用户函数和 `math.pi` 不受此规则影响。

Java 调用先确定各实参类型，再按[重载规则](molang-declarations.md#作者签名)选定唯一目标方法。固定标量参数、补齐后的实际参数与变长尾元素共用上文的标量转换表；候选合流与已确定参数目标的转换各自独立完成。合法调用即使在运行时会被 ACTION 或 subject 门禁拒绝，静态阶段也保留其全部参数约束；只有局部 missing、arity 或类型恢复才会删除调用 scope。Java 缺值消费见[声明边界](molang-declarations.md#值与-presence)，与通用语言转换及 `??` 的缺席规则相互独立。

Java 函数返回的有限 F32 保留原始 bit 位（含 ±0）。只有标注 `@MolangNullable` 的 `float`、`Float` 的非有限值以及 `Float` 的 `null` 归为类型化 missing；未标注的 `float` 默认保证有限且有值。这项边界规则只作用于 Java 函数返回值，不会传播到字段、getter、类型转换、变量存储或后续算术，见[声明边界](molang-declarations.md#值与-presence)。

类型依据只能来自有效的 producer、合法调用方或函数体内的消费约束：循环依赖不能自行证明类型，相互冲突且缺乏独立依据时也不会随意采纳先遍历到的一方。共享函数版本直接沿用所在顶层表达式的固定许可，不新建许可或函数深度窗口。源码里的数学函数同样先走 callable 恢复规则，合法调用再降级为闭集 intrinsic（`math.pi` 保持为字面量，损坏的底层 `MATH` 节点不享受局部恢复）；数学运算本身保证有限且必有值，不走 provider 门禁，同时保留实参消费、effect、权限和失败传播，具体职责见[数学 intrinsic](molang-declarations.md#数学-intrinsic)。所有合法调用都保证从左到右各求值实参一次；实参失败会阻止调用 provider，但已发生的实参或外围状态变更不回滚，普通动作沿[即时动作规则](molang-runtime.md#invocation-与效果)生效。

## 对象隔离与字段写

Java 返回的 record、只读数组及其元素都不可修改。Molang 对可写 record 执行字段写时，必须与原值隔离，确保其他别名永远看不到半写入状态；具体静态表示与复制时机见[对象表示实现](implementation/molang-runtime.md#静态表示与对象写)。

普通字段写按顺序执行三步：先捕获目标变量槽和当前接收者，再求值右侧表达式并做赋值转换，最后检查缺值、复制一份平面 record 并发布新值。因此右侧求值期间新建的别名仍观察旧值，右侧如果重新赋值该槽位也不影响第一步已捕获的接收者；如果中途失败，不会发布半写入结果。

对临时 Java 返回值写字段时，仅省去最终的槽位写回，仍依次执行接收者与 provider 调用、必要的返回检查、右侧求值和赋值转换。对普通 missing 执行字段写会在右侧求值后失败，与临时写规则不同。数组本身只读，只有数组中的 record 元素存入可写变量槽后，才进入可写隔离流程。

## 领域边界与失败

`ysm.defer` 的 Java 参数类型为 F32，固定参数与变长尾共用统一标量消费表，因此可以传入 BOOL、`String`、record 和只读数组。声音接口通过 `int` 与 `String` 重载选择精确方法后再交给内部声音 key，字符串 `"0"` 不会转成数字 ID。

对于持久 target，独立的 binding、类型或 shape 错误会按程序角色回退为声明的整程序 fallback（F32 为 `+0`、BOOL 为 `false`、VOID 为 no-op）；如果用户函数被替代，编译器会重新推导受影响的函数版本和调用方。节点级局部恢复与整程序 replacement 是分开的，只有最终入口仍不合法时才替换整条入口。失败原程序（primary）产生的类型、常量、effect 和签名不会残留在最终 artifact 中。

语言规则、声明事实、全部静态版本以及生成与执行兼容内容摘要，共同构成预期 artifact 身份（expected artifact identity）。遵循[开发期 Molang 契约](../../product-decisions/decisions/model-compatibility.md#bcdevelopment-molang-semantics-use-current-contract)，即便源码与 Java 签名完全相同，只要语义实现变了，旧产物也会失配并重新编译，引擎不保留旧转换、裸访问或权限的兼容分支。运行时只执行已确定的静态类型与源码控制流，不按动态值重选类型。Artifact 表示与编译事实见[运行实现](implementation/molang-runtime.md#源码解析与缓存)。
