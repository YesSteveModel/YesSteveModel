# Molang 静态语言规则

本页定义 AOT 编译路径下的静态定型、调用恢复、presence 传播与对象写入语义（由编译策略显式启用）。GUI 动态差异见[解释语义](molang-interpreter.md)（仅继承本页被引用的公共投影、控制流与数值规则），Java 扩展契约见[共同声明](molang-declarations.md)。

## 对象 presence

对象包括 `String`、平面 record（含 vector）、只读数组和精确 `Entity` 引用。空串、空数组、全零 record 与零向量均属有值（present）。

当上下文要求 F32 或 BOOL 目标值时，编译期按来源类型确定转换路径；来源表达式只求值一次，投影不改写来源自身的类型、内容或缺值状态：

| 合法来源 | F32 消费 | BOOL 消费 |
|---|---|---|
| 有限 F32 `x` | 保留原 bit 位，含 ±0 | `x != 0` |
| BOOL `false` / `true` | `+0` / `1` | 原值 |
| 普通 `unset`、脚本 `null`、类型化 missing | `+0` | `false` |
| 空 `String`、零长度只读数组 | `+0` | `false` |
| 非空 `String`、非空只读数组、其他非缺值对象 | `1` | `true` |

`String` 投影不解析数字（`"0"`、`"false"`、空白串均得 `1`/`true`）；数组仅检长度；全零 record 与零向量得 `1`/`true`。该表适用于算术、大小比较、逻辑、条件、循环次数、索引、入口返回、用户函数参数与 Java 标量参数。

- **相等比较（`==`、`!=`）**：
  - F32 与 BOOL 混合按数值比较。
  - 对象与标量比较时，先将对象按上表投影为 F32，标量保留原值（与左右顺序无关，如 `2 == true` 为 `false`）。
  - 同类型 `String`、record、数组按内容比较，`Entity` 按对象身份 `==` 比较（两 `null` 相等），均不调作者 `equals`/`toString`；不同对象 schema 禁止直接比较。
  - 已定型的 F32/BOOL/`String` 含缺值比较时，missing 分别按 `0`/`false`/`""` 参与（missing 与 missing 相等），不回写槽位。
- **`??` 与 presence 传播**：`??` 仅检测缺值（`0`、`false`、空串、空数组直接保留左侧，不求右侧）。缺值观察需求从 `??` 左侧沿槽复制、赋值、分支及用户函数参数/返回反向传播：被覆盖变量跟踪“已/未初始化”，其余变量不跟踪并在未写读或写缺值时归一为 `+0`/`false`/`null`/`""`/空数组。`Roaming` 必有值（初值 `+0`），其直接读取与已证明传播路径不求 `??` 右侧。临时 watch 沿用模型冻结表示，不反向开启初始化状态跟踪。静态分析覆盖所有有效写入，不做路径敏感初始化证明。
- **零与 `false` 字面量清空对象**：向已定型对象目标写入原始 F32 零字面量或 BOOL `false` 字面量触发同 schema 清空（未保留 presence 时归一为默认值，赋值结果与写入值一致），不授权跨对象类型互转。

## Literal 边界与定型

- **字面量资格**：前端将 `null` 直接编码为 `unset`。字面量资格取自常量折叠和转换前的原始规范节点：`(0)` 仍是字面量，而 `+0`、`-0`、`1-1`、调用、变量、赋值、条件与顺序表达式均非字面量。F32 的 ±0 判等视为零；非有限字面量拒收。
- **弱零与 `false` 依据**：F32 零字面量写入未定型位置仅作弱类型依据——同一约束流存在对象依据时解释为该对象缺值；仅剩弱零且允许默认类型时定型为有值 `0` 的 F32（`??` 不走右侧）。BOOL `false` 直接定型为 BOOL，仅当目标已由其他依据确定为对象时才作清空。表达式算出的零提供普通 F32 依据。
- **合流与冲突**：未声明类型的持久槽、局部槽、分支与同版本函数返回，仅允许 F32 与 BOOL 异型合流为 F32（纯 BOOL 流维持 BOOL）。缺值不构成类型候选也不提前转默认；对象与标量间、不同对象 schema 间构成类型冲突。
- **全 target 统一与函数特化**：持久槽跨全 target 所有入口及 subject/权限计划统一类型。用户函数按调用点的静态实参类型、供参形状与消费需求派生有限特化版本（单调用点弱零不向他处借用对象依据；同一版本类型固定，不按运行时值/presence/实体/scope/箭头深度拆分）。对象来源经赋值与返回传播，下游标量投影不反改上游类型。
- **递归与恢复重建**：递归函数组在入口固定成员签名，回边在允许的静态转换后须匹配入口签名（多态递归为编译期静态错误）。局部恢复后基于有效语法树重建函数版本、持久槽布局与 effect，失效版本不导出给临时编译。

## 运算符分组

优先级从高到低：调用/成员/索引 → 箭头 `->` → 前缀 `!`/`-`/`+` → 乘除 → 加减 → 大小比较 → 相等比较 → `&&` → `||` → 条件 `?:` → 空值合并 `??` → 赋值 `=` → `return`。二元运算左结合，条件运算右结合（真假分支从条件层解析），括号与语句块覆盖默认分组。

典型示例：
- `ref->q.x + q.y` 等价于 `(ref->q.x) + q.y`；`ref->q.x ?? 7` 可观察解引用产生的 missing。
- `a->b->q.x` 等价于 `(a->b)->q.x`，第二次解引用仍从外层 parent 进入（块内嵌套消费当前 child）。
- `1 ? null : 2 ?? 7` 等价于 `(1 ? null : 2) ?? 7`。
- 连续赋值 `v.a = v.b = 3` 因左结合报非法左值，须写 `v.a = (v.b = 3)`；条件分支内的赋值或 `??` 须加括号或块。

## 引用与箭头

- **`Entity` 引用**：保持精确对象身份，`null` 表示 missing。可经 `v.*`、`t.*`、条件、用户函数、只读 `Entity` 列表、`VALUE` 与冻结 transient 传递（不支持字段/方法访问、Roaming、网络同步或持久化）。标量消费时非 `null` 得 `1`/`true`，`null` 得 `0`/`false`，适用零/`false` 字面量清空。
- **箭头 `lhs -> rhs`**：在 parent 环境求值 LHS 一次（限 `Entity` 引用或 `unset`）。若为 `null`、目标已移除或跨世界，跳过 RHS 并返回对应 missing（`VOID` 为 no-op）；合法时在入口捕获目标最近完成样本，不要求目标安装模型，不获取目标执行权。目标移除后源变量槽不会自动清空：对引用用 `??` 仅查 `null`，对解引用结果用 `??` 才在目标失效时回退。
- **作用域归属**：RHS 支持语句块、赋值、循环与用户函数；`return`/`break`/`continue` 沿原词法边界传播。函数定义、变量槽、ACTION 许可、函数深度、动作与诊断全部留在源实体。可空派生（nullable derive）保留跳过边与未写状态。源槽覆盖或源实例结束时撤销引用根，目标关闭不等待源槽。

## 循环与函数深度

- `LOOP` 每次进入求值 F32 次数一次，迭代 `min(Math.round(count), 1024)` 次（非正数零次），各循环独立计数；`FOR_EACH` 按序遍历全部元素，支持 `break`/`return`。
- 活跃用户函数深度默认上限 32，第 33 层在求参前拒绝，仅成功进入者在 `finally` 递减。箭头与物理拆分 helper 共用源帧。深度超限仅截断当前顶层表达式，真实 provider 异常与清理失败按原 owner 规则隔离。

## 来源版本与除法

- **算术 `NaN` 归一**：算术运算产出 `NaN` 时静默归一为有值 `+0`；±Infinity 仍在有限值消费边界触发失败。AOT、GUI 解释与临时表达式一致。
- **`origin_ver` 除零回退**：接收模型 `origin_ver` 主版本号 `< 3` 时，除以 ±0 回退为有值 `+0`；`>= 3`、缺失或非法文本时关闭。版本号为点分隔十进制数字，可带非空 `-qualifier` 与 `+build`（字母/数字/点/下划线/连字符），全文匹配不修剪空白，前导零与超长数字不引起误判。
- **继承与范围**：`main`/`arm`、GUI 解释、默认补全与公共函数沿用接收模型选项；独立默认模型用自身版本；临时表达式沿用所借安装的冻结选项。开启与否均按左到右求值并标量消费两操作数一次，不吞实参失败；`%`、数学函数与 Java provider 内部除法不受影响。版本保留见[历史输入的单向投影](../asset-pipeline/implementation/conversion-and-export.md#历史输入的单向投影)。

## 调用解析与局部恢复

AOT 编译先对完整输入校验语法、编码与实际表示（不设节点数或深度人工额度），再按源码顺序解析符号：

- **符号与参数恢复**：不存在的符号恢复为普通 `UNSET`（已知种类用错形式如将变量当函数仍报独立错误）。Callable 参数数不符恢复为 `UNSET`；数量相符时从左到右逐参分析，遇首个有独立类型依据的边界失配即令整调用恢复为 `UNSET` 并停析后续实参，不吞并此前发现的独立错误。
- **外部函数无括号访问**：解析为外部 Java 函数时，`f` 与 `f()` 均作零参调用，共用重载、默认值、`argc`/变长尾、effect、门禁与失败来源，不缓存结果；最低参数数 `> 0` 时两者均触发局部 arity 恢复。返回 record/数组后可继续访问字段或索引，函数本身不可作左值。真实变量、context 属性、用户函数与 `math.pi` 不受影响。
- **重载与返回边界**：确定实参类型后按[重载规则](molang-declarations.md#作者签名)选定唯一方法，标量参数共用上文转换表；运行时可能被门禁拒绝的合法调用静态期仍保留参数约束。Java 返回有限 F32 保留 ±0，`@MolangNullable float` 与 `Float` 的非有限值/`null` 在返回边界归为类型化 missing（不向字段、存储或算术传播），见[值与 presence](molang-declarations.md#值与-presence)。
- **依据来源与数学降级**：类型依据须来自有效 producer、合法调用方或函数体内消费约束（循环依赖不自证，冲突不按遍历序偏袒）。共享函数沿用顶层固定许可。源码数学函数经 callable 恢复后降级为闭集 intrinsic（`math.pi` 保持字面量，损坏的底层 `MATH` 节点无局部恢复），详见[数学 intrinsic](molang-declarations.md#数学-intrinsic)。合法调用保证从左到右各求参一次，实参失败阻止调用 provider 但不回滚已发生变更，即时动作见[Invocation 与效果](molang-runtime.md#invocation-与效果)。

## 对象隔离与字段写

Java 返回的 record、只读数组及元素不可修改；可写 record 字段写与原值隔离，具体表示与复制时机见[静态表示与对象写](implementation/molang-runtime.md#静态表示与对象写)。

- **普通字段写（三步）**：捕获目标变量槽与当前接收者 → 求值右侧并做赋值转换 → 检查缺值、复制平面 record 并发布新值。右侧期间新建别名见旧值，右侧重写该槽不改第一步接收者，中途失败不发布半写入。
- **临时值、缺值与数组**：临时 Java 返回值字段写执行相同接收者/右侧求值与检查，仅省去写回；普通 missing 字段写在右侧求值后失败；只读数组中的 record 存入可写变量槽后才进入可写隔离流程。

## 领域边界与失败

- **特定声明入口**：`ysm.defer` 参数为 F32，固定参数与变长尾共用标量消费表；声音接口按 `int`/`String` 重载选择精确方法，字符串 `"0"` 不转数字 ID。
- **整程序 replacement**：持久 target 中独立的 binding、类型或 shape 错误按程序角色回退为整程序 fallback（F32 得 `+0`、BOOL 得 `false`、VOID 为 no-op）；用户函数被替代时重推导受影响版本与调用方。节点级局部恢复与整程序 replacement 分开，失败原程序的类型、常量、effect 与签名不残留在最终 artifact。
- **开发期语义身份**：语言规则、声明事实、静态版本及生成/执行兼容摘要共同构成预期 artifact 身份。按[开发期 Molang 契约](../../product-decisions/decisions/model-compatibility.md#bcdevelopment-molang-semantics-use-current-contract)，语义实现变化即触发缓存重编，运行期只执行已定静态类型与源码控制流，见[源码、解析与缓存](implementation/molang-runtime.md#源码解析与缓存)。
