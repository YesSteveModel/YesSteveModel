# 架构文档维护

本页补充架构文档的目录分层与契约写法，通用规则见[文档治理规则](../documentation-rules.md)。涉及产品语义冲突时按[产品维护规则](../product-decisions/maintenance.md)处理。

## 树状按需分层

`architecture/` 按“主干设计 + 按需加载叶子”组织，目的是控制阅读时的上下文占用：

- `architecture/README.md` 是唯一系统总入口，提供主数据流与按问题导航。
- **设计主干（`overview.md` 或同级专题页）**：承载本级职责、Seam Contract 与非显然设计取舍。折叠下级后，本级契约仍应自洽；父级只定义跨模块组合规则，不搬运下级内部接口。
- **实现叶子（`implementation/*.md`，可选）**：承载需要独立查阅的类级映射、状态机、门禁与所有权落点，供改动具体实现时按需加载。不要把 `implementation/` 的类级细节倒灌回 `overview.md`，也不要在 `implementation/` 里复述 `overview.md` 已说清的契约。
- **横向投影（`views/`、`flows/`，可选）**：用于跨子系统关系视图或单条跨域链路。只引用并汇总权威正文，不新增独有契约；无独立阅读价值时不建页。
- 目录约束：子系统内不设 `design/` 目录、同级 `README.md` 或实现总览；实现页与横向投影页不套用子系统四段模板，开头须链接到所落实的设计章节。

## 子系统入口结构

任意层级的子系统入口统一使用四个有序二级标题，并在页首用单行 `上级契约：[名称](相对路径#章节)` 声明直接上级（顶层子系统指向系统边界）：

| 章节 | 内容 |
|---|---|
| 职责与边界 | 职责范围、相邻边界及下级子系统入口 |
| Seam Contract | 本级跨边界契约正文，或按问题导航至外置契约唯一正文 |
| 设计取舍 | 非显然理由、代价与已知限制（不隐藏调用前置条件） |
| 实现与验证入口 | 核心责任映射链接、`status/` 已知差异与验证入口 |

### 契约页面组织

- **单项契约**：在 `## Seam Contract` 下按需选用规范六字段作为三级标题。
- **多项契约**：先用三级语义标题区分各 seam，在首段给出导览链接，再于各 seam 内用独占一行的加粗字段名按规范顺序组织适用字段。
- **按需省略**：无非显然增量信息的字段直接省略，不复述常识、共同规则或上游产品决策；对可演进的内部实现前提用中性事实语气描述。字段定义与语气准则见[设计指南](../development/design.md#架构契约格式)。
- **外置与共享**：篇幅较长或独立阅读价值高的契约可外置到同级专题页，入口页保留单链接导航，每个 seam 仅有一个权威拥有者；多份契约共享的非显然规则可设 `### 共同规则` 并以 `适用范围：` 开头。

## 关系用词与图形

| 用词 | 含义 |
|---|---|
| 上级生命周期 | 决定接纳或存续的作用域，不自动拥有底层资源关闭权 |
| 状态写入者 | 修改并发布某份可变事实的主体 |
| 保留者 | 通过强引用、lease 或 pin 保活资源的主体 |
| 关闭责任方 | 执行最终关闭或发起规定清理动作的主体 |
| 借用者 | 仅在指定窗口内访问资源的主体 |
| 共享范围 | 允许复用同一资源的消费者范围（不等同于共享可变状态） |

非线性关系优先用 Mermaid 图（标注边语义与必要偏序），多对象比较优先用表格。描述生命周期时明确区分：取消请求 vs 实际终态、发布资格 vs 合法旧使用、lease 关闭 vs 物理回收、对象寿命 vs 单次使用。

## 实现页准入标准

实现页仅收录删掉后会导致架构误判的映射信息（具体写入者、门禁、所有权转移点、共享身份或非显然并发窗口）。局部算法步骤、调优常数、全量成员清单与测试快照直接留在代码或测试中。如果某份实现页只剩设计复述则删除；仅剩少量类型映射时直接收进设计页的“实现与验证入口”。
