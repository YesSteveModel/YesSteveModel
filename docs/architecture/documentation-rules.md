# 架构文档维护

本页定义架构文档的专用规则，通用要求见[文档治理规则](../documentation-rules.md)。产品含义变化或冲突按[产品维护规则](../product-decisions/maintenance.md)裁决；文档整理不改变生产契约。

## 组织与递归展开

`architecture/README.md` 是唯一系统入口，拥有系统核心模型及按问题导航。具有独立目录的子系统以 `overview.md` 承载核心设计；单页子系统使用所属职责的语义文件名，不必为契约新建目录。设计专题与入口同级，实现映射按需进入 `implementation/`。不设子系统 `design/`、同级 `README.md` 或实现总览，也不要求设计与实现页对称。

本级应能独立解释输入、结果、责任、发布条件、失败后果与结束义务。下级可细化节点、交接或生命周期；折叠下级后，本级契约仍成立。父级拥有组合规则，下级拥有局部接口，父级不复制全部接口、状态和例外。跨分支规则归实际组合责任方，不按最近公共目录机械上移。

子系统按责任识别，不按目录或页面识别，递归分解不限制深度。拆分应具有独立职责与结果、状态或资源责任、交接与失败边界，以及局部阅读价值。线程、package、类、篇幅或目录对称不能单独证明边界。只有重复摘要或符号列表时合并；交接专题不自动成为子系统。上级职责入口应直接列出下级子系统的契约入口，专题依赖另作说明；不另建全仓身份台账。

## 设计入口结构

任意层级的子系统入口使用以下四个二级章节，单页子系统与目录子系统使用同一结构。专题不套用子系统模板；无长期实例时在契约中说明操作由哪个调用作用域承载。

| 章节 | 本级应解释的内容 |
|---|---|
| 职责与边界 | 职责概述、相邻边界及下级子系统入口 |
| Seam Contract | 本级契约的统一入口，按消费者问题导航到各 seam 的唯一正文 |
| 设计取舍 | 契约背后的非显然理由、代价与限制，不另定义调用义务 |
| 实现与验证入口 | 必要责任映射、status 差异与验证入口 |

契约划分、共同规则和六字段格式见[设计指南](../development/design.md#契约与责任)。

入口以 `上级契约：[名称](相对路径#章节)` 显式声明直接上级，并说明所细化的职责。上级可以是同目录的另一个单页子系统，不能由目录自动推定；顶层子系统链接系统边界。上级不自动拥有全部 backing，交互仍可形成图。

### 契约页面组织

单项契约可直接使用六个三级字段标题。多项契约先用三级语义标题区分 seam，再用独占一行的加粗字段名组织六字段。必要细节使用唯一语义标题；可选的“共同规则”章节明确适用契约与义务。

短契约优先同页；需要独立阅读时放在已有职责专题，新页按职责命名。入口用语义章节链接外置契约的唯一正文，并说明消费者的问题。不同入口可以依赖同一契约，拥有者只有一个；导航摘要不复制完整规则。

章节应能精确引用交接及依赖，不增加逐 seam ID、版本号或全量 API 台账。

## 关系用词与图形

| 用词 | 固定含义 |
|---|---|
| 上级生命周期 | 决定接纳或存续的作用域，不自动拥有 backing 关闭权 |
| 状态写入者 | 修改并发布某份可变事实的主体 |
| 保留者 | 通过强引用、lease 或 pin 保活资源的主体 |
| 关闭责任方 | 执行最终关闭或发起规定清理动作的主体 |
| 借用者 | 只在指定窗口访问资源的主体 |
| 共享范围 | 允许复用同一资源的消费者范围，不等于共享可变状态 |

探索非线性关系优先用拓扑图，比较 owner 职责或事件影响优先用表格；文字补充条件和例外。每张图说明抽象范围与边的含义；请求、数据、持有和必需顺序使用标签或线型区分。颜色不单独表达语义，不把并行关系画成虚假的统一状态机。简单线性事实可直接陈述。

应区分取消请求与真实终态、发布资格与合法旧使用、lease 关闭与物理回收、对象寿命与单次使用、服务结束与进程结束。只记录必要偏序。Ownership 转移应说明成功条件和失败后责任；多个保留者不等于多个关闭裁决者。

## 实现信息准入

每个独立信息块应同时通过以下三道门槛：

| 门槛 | 判断 |
|---|---|
| 架构关联 | 落实哪个具体契约、职责边界或承重选择？ |
| 独立增量 | 补充哪个设计未定义的必要写入者、门禁、转移点或共享身份？ |
| 最低精度 | 删除具体结构、步骤或数值，是否会丢失该责任关系？ |

保留信息应能解释省略后会导致哪项架构误判。代码难以还原、局部算法需要正确、调试便利或已有正文，均不能单独证明价值。可替换的责任映射仍可保留，不以可替换性单独判删。产品和标准约束遵循各自的权威规则。

私有布局、算法步骤、调优数值、成员清单、测试快照和迭代过程通常不进入实现页；通过准入门槛的必要责任关系可保留。验证与状态证据链接其权威入口。跨类、目录、线程或 Java/native 不自动构成架构边界；递归拆分不改变信息资格。局部知识是否需要注释或测试，应另行判断。

### 页面保留与定位

实现页与整个 `implementation/` 均可不存在。只剩设计复述时删除；只剩少量责任符号时放入设计的“实现与验证入口”；独立解释必要映射时才保留专题。不设篇幅或数量指标。

实现页开头链接精确设计章节并说明落实关系；符号定位遵循通用[写作约定](../documentation-rules.md#写作约定)。

## 流程与横向导航

`views/` 用于跨职责树的关系投影或多场景比较；`flows/` 用于单个跨域场景的展开。两者均可选，不套用子系统入口结构，不建立自己的 overview，也不为同一问题重复建页。已有设计正文能独立解释关系时直接链接正文。

视图应有明确阅读问题。允许为连通拓扑和比较事件而重复必要摘要，每组关系应精确链接其权威章节；只有一组跳转链接不能代替跨域关系说明。

图表达共享关系与必要偏序，分别标明边的含义；表格按 owner 或事件比较归属、保留、关闭责任与结束条件。配额摘要注明适用范围、计价对象及归还条件，不把局部预算相加为总内存上限。不要建立全量资源、成员、线程或参数台账。视图不能新增契约、保存已裁剪细节，也不能代替实现页所依赖的设计正文。发现独有规则时，先归入实际责任方的正文，再保留投影。

系统入口同时提供按问题导航与横向视图入口。只读视图应能解释其声明范围内的关系，精确条件和例外可沿链接进入正文。是否删除视图取决于阅读价值，不以没有独有规则作为删除理由。

## 修改与验证

定位受影响的产品依据、权威设计和必要当前映射。按[信息取舍与维护](../documentation-rules.md#信息取舍与维护)筛选事实和修复引用，并按需更新产品 Landing、反向索引及复杂度依据。未落地差异归 status，未选择方向归 future。

复核受影响的边界与场景，包括身份、裁决者、写入者、保留/关闭方、门禁和终态。只读父级应能解释边界行为，折叠下级不得改变契约。未闭合冲突不能因链接有效而判定完成；发现依据缺口时定向核验。

执行通用[文档检查](../documentation-rules.md#文档检查)。结构与引用检查不判断承重价值或消费者完整性。
