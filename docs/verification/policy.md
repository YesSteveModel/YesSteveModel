# 验证边界

产品决策确定应保证的行为、支持范围与优化优先级；本页只界定验证投入与证据解释方式，不增加额外的产品承诺。

## 性能验证

[工作量与服务端软目标](../product-decisions/decisions/workload-budget.md)及[基础设备参考](../product-decisions/decisions/device-quality.md)用于横向比较优化收益。参考设备、100 人成本目标以及面向未来 Bukkit 的 200 人观测范围均停留在产品层：它们不作为当前开发阶段每次变更的硬验收门槛，也不豁免普通错误隔离与主循环保护义务。

300 人极限压力测试仅用于探测系统上限，不承诺在该规模下稳定提供服务。每次改动应按涉及的工作量选择最小相关验证集；凡报告帧率、MSPT 和卡顿峰值（lag spike），必须附带对应的内容规模与运行环境，未跑完完整压测不得记作性能达标。

## 视觉验证

固定场景及人工与 AI 检查的分工见[视觉一致性验收](../standards/conformance.md#视觉一致性验收)。文档校验、单元测试与基础视觉检查各自只能证明所覆盖的层级，不能替代真实游戏、模组联动或高级渲染效果的验收。

## 验证分层架构

全部自动化与手工验证按职责划分为四个正交层级，各层只负责证明自己覆盖的边界，不得互相冒充或重复造轮：

| 层级 | 默认入口 | 耗时目标 | 负责证明 | 明确不负责 |
|---|---|---|---|---|
| L0 静态门禁 | `./gradlew test`、`shadowJar` 校验 | < 1 秒 | Dedicated Server 字节码可达范围不引用客户端类、发布包不含测试控制面、注解处理器产物契约 | 运行时并发、真实性能与真机渲染 |
| L1 确定性契约单测 | `./gradlew test`（纯单测） / `./gradlew serverMockTest`（百人模拟传输契约） | < 30 秒 | 格式/协议与跨边界畸形输入、AOT 与解释器语义等价、缓存原子发布、资源租约归属；`serverMockTest` 独立负责百人并发/背压/重载不变量 | 真实 MSPT 数值、真实 Netty/OS Socket、MC 渲染线程与 GPU |
| L2 无头负载与微基准 | `serverScaleLoad` / `benchmark`（按需 + JFR） | 1–5 分钟 | 100/200/300 人并发在线 + 目录重载 + Netty 水位背压下的 MSPT 增量、lag spike 与 gameplay 延迟；Molang/JNI 微基准 | Forge 客户端 UI、着色器/OpenGL 渲染、多模组联动 |
| L3 真机 Forge 冒烟 | `runServer` + `runClient`（发版/宿主改动按需） | 2–5 分钟 | Forge 频道握手、真实登录/重载/切模/断线重连、主循环渲染与音频不崩溃、基础视觉一致性 | 细粒度参数组合或百人规模压测 |

## 单元测试维护规则

1. **契约优先，禁测实现细节**：断言只能依赖公开 API 或架构 Seam 契约的可观察输出、状态迁移与资源释放。禁止通过反射读写私有字段/方法，禁止对生成字节码类名或字段名做正则断言，禁止保留“证明旧重载或旧字段已删除”的墓碑测试及常量自证测试。
2. **禁止伪造 Minecraft / Forge / OpenGL 宿主**：凡需 `Unsafe.allocateInstance(Minecraft.class)`、反射改写 `Bootstrap`/`RenderSystem` 静态字段或手写字节码改写 `ClassLoader` 才能执行的测试，不属于 L1 单元测试；应剥离无宿主依赖的纯逻辑单元测，其余交由 L3 真机冒烟覆盖。
3. **禁止面向测试污染生产代码**：不得仅为了单元测试或故障注入而向生产类添加包私有“超级构造函数”、无生产多实现的策略接口、生产零实现的注入 `Hook`，或仅测试调用的白盒计数方法（如 `readyCount()`/`activeCount()`）。测试替身注入只允许发生在显式定义的架构 Seam（如 `TransportPort`）。
4. **按信任边界投入防御性测试**：内部 Seam 的调用前置条件由契约和类型系统约束，不机械逐条翻译为单元测试；畸形输入与异常路径测试聚焦跨信任边界（网络协议帧、资产容器与旧格式解码、用户输入与第三方扩展接入）。
5. **确定性、默认可运行与体积控制**：L1 单元测试必须默认可通过 `./gradlew test` 确定性执行（除显式标注的 JNI native 边界测试外，禁止依赖隐式环境变量），禁止使用 `System.gc()` 或长 `Thread.sleep()` 轮询。同构场景强制使用 `@ParameterizedTest` 或数据表驱动；单个测试文件软上限约 400 行；一次性阶段验收脚本或证据框架在里程碑闭环后应及时清理，不长期滞留主测试集。
